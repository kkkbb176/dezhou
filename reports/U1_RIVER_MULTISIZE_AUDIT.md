## A. 已核实的生产调用链

```text
analyzeManualHand
  └─ buildDecisionContext（contextBuilder）
       ├─ 4d raiseResponse 块
       │    grid      = buildSizeGrid(legal, computePot(state), 'RAISE')
       │                = round(toCall × [2, 2.5, 3, 4, 5, 6, 8]) + minRaiseTo + allInTo（去重、丢弃 < minRaiseTo）
       │    desiredTo = computePot(state) + 2 × heroCallCost
       │    raiseTo   = closestSizeTo(grid, desiredTo)        ← **只选一个尺寸**
       │    buildRaiseResponse({ currentPot, heroAdd, villainAdd, heroContestedAdd, finalPot, ... })
       │    rangeEquityOf(callContinueEntries, seed = equitySeed + 1601)
       │                = computeEquity(..., { mode: FAST, iterations: 6000, opponentWeights })
       │                ⇒ 本节点实际**升级为 EXACT 枚举**（73 组合，无抽样误差）
       │    raiseEV   = raiseEVOf(...)                        ← 生产唯一公式
       └─ 其余 7 个合法尺寸 ⇒ `unevaluatedActions` + `RAISE_EV_NOT_IMPLEMENTED` 披露（不参与比较）
  └─ decideAlpha → chooseByEvidencePriority（argmax FOLD≡0 / CALL(PROXY_EV) / RAISE(MODEL_EV)）
```

本节点实测：`pot = 73`（= `math.pot`）｜`callCost = 20`｜`winnable = 93 = previewCommit(hero, 20).winnable`｜
`callEV = 0.435849 × 93 − 20 = 20.533985`（独立复算逐位一致）｜网格 = 8 个金额｜`desiredTo = 73 + 40 = 113` ⇒ 选中 **120**。

## D. 再加注分支：实际实现与潜在缺陷

**实现**：`raiseEVOf` 第三项 = `P(再加注) × (−heroContestedAdd)`，即**假定 Hero 必然弃牌**、损失本次全部投入；
`heroIsAllIn ⇒ P(再加注) ≡ 0`（本节点 174 处实测 0.00% ✔）。模型**不建模**「Hero 跟注对手的再加注」。

**合法性（本节点实测，已纠正我自己的一个误判）**：

| 情形 | 尺寸数 | 说明 |
|---|---|---|
| 可做**完整**再加注（≥ 最小加注额） | **58 个**（加注至 ≤ 97） | 他需要 (R + R − 20) − 20 筹码，够 |
| 只能**全下 under-raise**（低于最小加注） | **76 个**（98 … 173） | 他的全下 174 < 最小再加注到（如 R=120 时需 220）⇒ 只能推 174 |
| 跟注即全下（连跟注都投光） | **1 个**（174） | 此时 **Hero 也恰好全下** ⇒ rr = 0 ✔ |

⇒ **本节点不存在「分支非法」的情形**（`canRaise` 的判据是加注权未关闭，不足最小加注的全下仍合法；
`buildSizeGrid` 也无条件保留 `maxTo`）。**因此就本节点而言，我先前「76 个尺寸分支非法」的读法是错的，此处撤回。**

### 🔴 D-0 **但是：缺陷在其它节点上真实存在（独立复核确认，我此前的撤回过度了）**

复核者用**引擎级重放**（`createGame` + `applyAction` + `computeLayeredPot`）证明：
**当「跟注即把对手自己的筹码投光」时，他不可能再加注**（跟注后 `bettingRoundComplete = true`，
再 `RAISE` 被引擎以 `ACTION_AFTER_HAND_OVER` 拒绝），而模型**仍会给出再加注权重**——
因为 `buildRaiseResponse` 只看 `strength / required / raiseScale / ratioToPot / heroIsAllIn`，
**从不看对手筹码**，调用方也只传了**已封顶**的 `villainAdd`，没有告诉模型「他这一跟就是全下」。

**最小复现就在仓库自己的夹具里**（`test/raiseEvCashflowP0.test.ts:325` 的 P0-7 节点：
Hero BTN 100BB A♠K♠ vs BB **30BB**，河牌 BB 下注 10BB）：

```text
pot 73｜callCost 20｜R = 120｜heroAdd 120｜villainAdd 14（raw 100，他河牌下注后**只剩 14**）
villainAdd === 他的全部剩余 ⇒ 他这一跟就是全进 ⇒ 他不能再加注
模型：P(弃/跟/再加) = 0.0530 / 0.5160 / **0.4311**   ← 43.11% 的不可能分支，每单位质量按 −34 计
引擎：BB CALL 14 → allIn=true、bettingRoundComplete=true；随后 RAISE → ACTION_AFTER_HAND_OVER ❌
```

**EV 失真（精确恒等式，质量守恒）**：`EV_corr − EV_model = finalPot × P(再加注) × eq_R`
⇒ 失真 ∈ `(0, P(再加注) × eq_C × finalPot]`，方向**恒为低估加注**：

| 节点 | P(再加注) | eq(跟注桶) | finalPot | 失真上界 | 点估计 eq_R=0.25 | 模型 → 修正后 |
|---|---|---|---|---|---|---|
| P0-7 夹具（100/30BB，河 10BB） | 0.4311 | 0.6270 | 121 | **32.7** | +13.0 | +10.81 → **+23.85** |
| S6（100/40BB，河 15BB） | 0.4467 | 0.5642 | 161 | **40.6** | +18.0 | −1.35 → **+16.6**（越过 FOLD≡0 零点） |
| S8（300/40BB，河 20BB） | 0.5006 | 0.4909 | 161 | **39.6** | +20.2 | −11.46（`decisionMargin = CLEAR_FOLD`）→ **+8.7** |

**发生率（复核者扫描 87 个节点）**：81 个 `rr>0`，其中 **23 个 rr>0 而对手已被自己的筹码封顶**
（全部 `EXP` 模板、BB ≤ 80BB），`P(再加注) ∈ [0.207, 0.501]`，单节点失真 **34.4–46.6 筹码**。
**现有测试完全没有覆盖这种情形**（`raiseResponseU1` / `raiseEvCashflowP0` 只锁了 **Hero** 全下）。

⇒ 这是**确凿的 P1 缺陷（非法分支）**，与我下面 D-1 的「分支语义过粗」（合法但下界过松）是**两个不同的东西**：
本节点（KQ）只出现前者之外的情形，但**仓库自己的夹具就能复现后者**。

### 🔴 D-0b 同一根因还存在于**既有**的「Hero 下注 → 他响应」通路（`betResponse.buildResponseModel`）
该通路对 **Hero 全下**有守卫（`raiseShare = heroIsAllIn ? 0 : …`），但 `legalizeBetSizes` 会把下注额封顶为
`min(heroRemaining, villainRemaining)` ⇒ 「下注额 = 对手全部剩余」是合法候选，而响应模型照样产出加注桶。
实测（Hero 100BB / BB **20BB**、转牌 7.5BB、**河牌 BB 过牌**、pot 53）：唯一合法尺寸 = 14 = 他全部剩余（`wasCapped=true`），
`P(弃/跟/加) = 0.0992/0.8485/**0.0523**` ⇒ 同一类不可能分支（此节点量级小，贡献 ≈ +0.15 筹码）。
**该模块属既有已验证模块，本轮只报告、不修改。**

**其余检查**：① `ReraiseBranchEV` 在本节点确实恒为 `−heroAdd` —— 且复核给出**可证**理由：
`rr > 0` 要求对手跟完仍有筹码 ⇒ 他的跟注未被封顶 ⇒ `heroContestedAdd === heroAdd` 恒成立
（两者不等**只**发生在被封顶的情形，而那正是 D-0 里「分支本不该存在」的情形）；

**真正的缺陷（P1-2）**：**分支语义过粗 + 下界极松**。在他只能 under-raise 的尺寸上，Hero 其实只需补一小笔：
R=120 时他全下 174 ⇒ Hero 再补 **54** 进入 **421** 的终池 ⇒ 跟注只要 **12.8%** 权益即可；
模型却按「弃牌、损失 120」计入，权重 16.9% ⇒ **−20.3 筹码**。

| 加注至 | 他的全下 | Hero 还要补 | 跟注后终池 | 跟注只需权益 | 模型的该分支值 | 该分支对 EV 的影响 |
|---|---|---|---|---|---|---|
| 40 | 174 | 134 | 421 | 31.8% | −40 | −16.5 |
| 60 | 174 | 114 | 421 | 27.1% | −60 | −13.0 |
| 80 | 174 | 94 | 421 | 22.3% | −80 | −16.8 |
| 100 | 174 | 74 | 421 | 17.6% | −100 | −20.5 |
| 120 | 174 | 54 | 421 | 12.8% | −120 | −20.3 |
| 160 | 174 | 14 | 421 | 3.3% | −160 | −26.4 |

⇒ RAISE EV 是**宽松下界**（方向偏保守 = 偏向不加注），偏差量级 **13–26 筹码**，
**大于** CALL 与最优尺寸之间的差距（9.8 筹码）。**因此当前模型不足以证明「本节点 CALL 更优」。**

**其余检查**：① `ReraiseBranchEV` 在本节点确实恒为 `−heroAdd`；② 「Hero 面对任何再加注必然弃牌」是显式假设；
③ 对手筹码不足 / 最短再加注的处理**未建模**（只影响分支语义，不影响合法性）；④ 无非法分支（见上）；
⑤ **Hero 可以跟注**（未全下时），但未建模；⑥ 未计算后续跟注的成本/终池/条件权益；⑦ 河牌全下时**不再生成**后续再加注 ✔。

## E. 画像样本与概率计算的证据（任务 C）

**数据流（引擎自述 + 直接调用 resolver 双重取证）**

| 问题 | 实测答案 |
|---|---|
| `foldToRiverBet 16%` 的分子/分母 | **successes 19 / opportunities 120**（`approximated = true`：机会数由 `1200 手 × 频率` 近似，**不是逐手实测**） |
| 实际河牌决策样本数 | **≈120 手**（1200 手的 10%） |
| 收缩后的有效值 | `observed 0.16 → effective **0.2975**`（先验 0.38、先验权重 200、confidence 0.375） |
| 面对下注 / 面对加注是否分开统计 | **没有分开**。且 U1 的加注响应**完全不读**该统计 ⇒ 「把面对下注的弃牌率当面对加注的弃牌率」这个错**没有发生** |
| `foldScale/callScale/raiseScale` 的来源 | `responseTendenciesOf` 中**只由手选标签维度**算出并按画像可信度缩放：`callScale = 1+(0.30·passive−0.18·tight−1)·conf` 等；本节点 = **1.088 / 0.903 / 0.958**（标签 = CALLING_STATION、conf = 0.35） |
| 不同尺寸如何影响三个概率 | 只通过**价格门槛**（`villainAdd/finalPot`）与再加注门槛，与统计无关 |
| 是否重复加权 | **否**（未发现同一统计经两条通道重复施加） |
| 是否用 Hero 权益反推对手概率 | **否**（U1 只用公共强度带 + 听牌 + 价格 + 标签倾向） |
| 概率是否恒归一 | **是**（实测 P(弃)+P(跟)+P(再加注) = 1.000000000000） |
| 低样本是否退回先验 | **是**（收缩机制：先验权重 200 对 120 次机会） |
| confidence 0.300 / 容差带 ±4.65 | 0.300 = 决策层 `adjustedConfidence`（标签上限 0.35 的进一步衰减，band = MEDIUM_LOW）；±4.65 = **5% × winnable(93)** |

**🔴 决定性单变量实验（P1-1）**：同一节点**带 / 不带**这 1200 手统计，**11 个决策相关字段逐位一致**
（动作、CALL EV、EqVsBetRange、EqVsArrivalRange、RAISE EV、P(弃)/P(跟)/P(再加注)、EqVsRaiseCallRange、理由链）。
独立复核（子代理）在**同一节点**给出同样结论：三个响应概率**逐位相同**
（`0.16952719033920757 / 0.6611688848970236 / 0.16930392476376954`），
并且 `callScale 1.0882 / foldScale 0.9027 / raiseScale 0.9580 / bluffRaiseScale 0.9633` **完全由标签 × 0.35 可信度产生**
（`responseTendenciesOf(ARCHETYPE_DIMENSIONS.CALLING_STATION, 0.35, null)` 逐位相同）。

**⚠️ 对上一版报告的一处更正**：我此前用 `actionContext: null` 探针得到「RIVER 分街系数非中立
（0.858/1.142/0.668/0.640）」。复核指出**在生产节点上这些系数其实是中立的 1**——
本节点的动作语义被判定为 `FACING_DONK`（BTN 是转牌进攻方、BB 河牌领打），
`isTraitAllowedInContext` 因此**拒绝**了 `foldToRiverBet` 等分街条目 ⇒ `foldScale = callScale = 1`。
两者并不矛盾（探针无 gate、生产有 gate），但**结论以生产为准**：本节点分街统计被语义门拦掉，
且**即使被放行**（如 `FACING_CBET` 时 `foldScale = 0.85825`）U1 模型也**不读**它。

⇒ **结论**：统计在**本节点族（Hero 面对下注 → CALL/RAISE）上被计算、却没有被消费**——
该链路的响应概率完全由**主观标签**（可信度 0.35）驱动。消费 V3 分街系数的是 `postflopAdvisor` /
`classifyResponse`（「Hero 下注、他响应」那一类节点），不是 U1 的加注响应链。

**🔴 附加发现（P1-3，独立复核提供并已由其逐位取证）**：`responseTendenciesOf` 的三个调用点
**用了不同的维度来源**——U1 加注响应（`contextBuilder:3850`）与下注范围（`3717`）用**标签维度**，
而 `betDecision`（`4353-4364`）用**融合后的 `resolvedDimensions`**。
同节点实测两者不同：U1 `call/fold = 1.0882/0.9027` vs bet 模型 `1.078984/0.911353`。
`observedStats.ts:1625-1629` 明文要求「开火倾向与响应模型必须用同一套全局维度」，U1 **没有遵守**。

**反「重复加权」取证**：`STAT_DIMENSION_POLARITY` 对全部 `FoldTo*CBet` / `*CheckRaise` 均为 0 ⇒
它们**不进维度**；实测 `foldToRiverBet = 0.16 / 0.60 / 缺失` 三种情形下 `resolvedDimensions` **完全相同**；
`behaviorProfileOf` 在生产中**从不传 `observed`** ⇒ 也没有「统计经下注范围二次施加」的隐藏通道
（实测 `bettingRangeFacts` 与 `heroEquityVsBetRange` 带/不带统计逐位一致）。

另有 **P2 呈现缺陷**：诊断 `player` 块自述 `handsObserved = 0`、`sampleSize = undefined`、
「无实测数据，采用用户手选画像」——**与内部事实不符**（统计已解析）。
根因（复核定位）：`observedStats.handsObserved` **只进 `PlayerProfile`、从不进 `PlayerSnapshot`**
（`contextBuilder:2787, 2871`），因此 1200 手**也不会提升界面上的可信度**。
另有文案缺陷：统计 trace 印「伪计数 6」而收缩实际用 `K = 200`（`observedStats.ts:797`）。

## 复核口径的已知偏差（诚实标注）

本报告的逐尺寸表用**生产同源**方法复算，但**对手画像输入是重建的**：
`scripts/u1-river-multisize-audit.ts` 构造 `buildPlayerSnapshot` / `buildRangeSnapshot` 时未传
`behaviorProfileOf(...observedStats...)`（生产会传）。后果实测：同一尺寸（120）处
`P(跟) = 66.05% vs 生产 67.05%`、`RAISE EV = −9.254 vs 生产 −8.700`（差 **0.55 筹码**）。
该偏差**不影响**本报告的任何结论：CALL 与最优尺寸的差距 9.8 筹码、再加注分支偏差 13–26 筹码，
均为其 18–47 倍。产品**自身**在 120 处的数字仍以 `reports/evidence/kq-river-decision.txt` 为准。

## 一句话结论

**生产引擎没有候选动作遗漏、没有资金流遗漏**（资金量在 D-0 的引擎重放里逐位正确），
但有 **一个确凿缺陷 + 三个 P1 级模型/接线问题**：

1. **P1-2a（确凿缺陷）**：对手「跟注即全下」时仍生成再加注分支 —— 复现就在仓库自己的 P0-7 夹具
   （`rr = 0.4311`，引擎实测该分支不可能存在），扫描 23/87 个节点中招，单项失真 34.4–46.6 筹码；
2. **P1-2b**：再加注分支用「弃牌」代替「Hero 可以小额跟注」，下界过松（13–28 筹码，S1 可达 +28）；
3. **P1-1**：用户提供的 1200 手统计**根本没有参与决策**（带/不带逐位一致）；
4. **P1-3**：同一份画像被两套维度来源使用（U1 用标签维度、bet 链路用融合维度）；
5. P2×3：只评估一个启发式尺寸、诊断自述与事实不符、trace 文案印错收缩强度。
   （另：P1-4 同一根因存在于**既有**下注通路，本轮只报告不修改。）

**因此「本节点 CALL 更优」这一结论在修复 P1-2a/P1-2b 之前不能被视为已证明。**
