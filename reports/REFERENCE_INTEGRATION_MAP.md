## 0. 融合的四条铁律

| # | 铁律 | 落地位置 |
|---|---|---|
| 1 | **数学真值只能来自确定性代码**，外部资料永不参与计算 | 既有架构（`handEval` / `odds` / `equity`） |
| 2 | **理论基线与牌池经验必须分开标注**，不得互相冒充 | `EvidenceLevel` + `RangeProvenance` |

## 2. 逐模块映射

### 2.1 Poker Core / Math Engine —— **不接受任何外部输入**

| 项 | 结论 |
|---|---|
| 数学真值来源 | **只有本项目自己的确定性代码**（`handEval` / `fastEval` / `odds` / `equity`） |
| 外部资料能否进入 | **否**。任何书籍、GitHub、求解器输出都不得进入数学层 |
| 理由 | 规范第 1 节 A 类：数学真值必须**可验证**；外部资料无法在本项目内复现 |

> 这是一条**结构性**保证：`src/domain/knowledge/` 不导入 `handEval` / `odds` / `equity`，
> `src/domain/range/gameEnvironment.ts` 也不导入它们（已有源码扫描测试）。

### 2.2 Range Engine —— 接受**来源元数据**，不接受**范围数值**

| 可接受 | 不可接受 |
|---|---|
| 来源类型 / 可信度上限（已有 `RangeProvenance`） | 从书籍抄来的 169 类范围权重 |
| 「被编辑过的数据必须重新检查」这条纪律 | 从无许可证项目复制的范围数据 |
| 环境先验的**方向**（更宽 / 更窄） | 环境先验的**具体幅度** |

| 来源 | 融合形式 | 状态 |
|---|---|---|
| GTOpen 的「被编辑范围必须对照历史概率重新检查」 | 强化既有规则：复制/编辑过 → 降级为 `FALLBACK` | ✅ 已一致 |
| poker_solver 的「聚合器输出不得用于范围级问题」 | 写入交叉验证方案 | ✅ 已采纳 |

### 2.3 Player Profile —— 本轮融合最多的模块

| 来源 | 融合内容 | 形式 | 状态 |
|---|---|---|---|
| GTOpen | **证据标签描述来源而非置信度** | 设计原则（与本项目 `RangeProvenance` 同构） | ✅ 已采纳 |
| GTOpen | **玩家统计是连续谱而非聚类** | 独立印证「标签只是摘要」 | ✅ 交叉印证 |
| GTOpen | **翻牌前类型不预测翻牌后行为** | 新增规则 `profile.preflop-type-does-not-predict-postflop` | ✅ 已登记 |
| GTOpen | **Nit 与 Maniac 是最值得优先识别的两类** | 规则 `profile.nit-and-maniac-most-valuable-reads`（**HEURISTIC，无幅度**） | ✅ 已登记为待验证假设 |
| 书籍 | 玩家类型 → 调整映射 | **无正文，仅占位** | ⬜ 待正文 |

> ⚠️ **重要**：GTOpen 的玩家原型统计**数值一律不得引用**（无许可证）。
> 本项目登记的规则引用的是**方向性结论**，且规则注释中已写明这一点。

### 2.4 Dynamic Human Behavior（Step 7）—— 只接受**概念**

| 来源 | 融合形式 | 限制 |
|---|---|---|
| The Mental Game of Poker | Tilt / chase-loss / outcome bias 的**概念框架** | 无正文；且**心理描述绝不能成为数学真值** |
| GTOpen | 「Point lock」与「自适应求解」的粒度概念 | 需要求解器，暂不可用 |

**硬约束**（规范第 12 节）：心理类知识只能影响「偏移概率」，
最终动作仍由 Math × Range × Profile × Dynamic × Environment 产生。

### 2.5 Exploit Engine —— 需要先有可校准的参数

| 来源 | 融合形式 | 状态 |
|---|---|---|
| GTOpen | node locking + 重新求解的**架构方向** | 🟡 概念，需求解器 |
| 四本书 | 弱玩家利用框架 | ⬜ 无正文 |
| 内部牌局数据 | **当前唯一*已经可执行*的参数来源** | 🔴 尚无数据 |
| 可授权 / 可追溯 / 场景匹配的统计数据集 | 未来的第二条路径 | ⬜ 未找到（本轮四个项目都不满足） |
| 可本地复现并交叉验证的 Solver 输出 | 未来的第三条路径 | ⬜ 需第二实现 + 算力 + 许可证评估 |

> ⚠️ **不是「唯一来源」，而是「当前唯一可执行来源」。**
> 详细的四条准入条件见 `docs/KNOWLEDGE_POLICY.md` §3.2。
> 写成封闭断言会在条件变化后变成错误的约束 —— 那是本文件初版的缺陷，已更正。

> **诚实结论**：Exploit Engine 在当前状态下**无法参数化**。
> 唯一可行的参数来源是本项目自己的真实牌局数据（规范第 54 节的最后一步）。

### 2.6 Cooler / Bad Beat / Leak 分类 —— 不依赖外部知识

| 项 | 结论 |
|---|---|
| 分类依据 | **Decision Snapshot 重新分析**（规范第 23 / 24 节） |
| 外部知识能否影响 | **否** —— 一旦允许外部知识影响分类，就退化为「结果导向」 |
| 需要的知识 | 只有**定义**（见 `reports/CASE_TAXONOMY.md`） |

### 2.7 实盘复盘 / Case Library —— 接受案例，**拒绝答案**

| 来源 | 融合形式 |
|---|---|
| Live No-Limit Cash Games | 案例素材（⚠️ 需标注 `gameType = LIVE_CASH`，与项目线上环境不同） |
| 用户自录牌局 | 案例素材（主来源） |

**三条硬约束**：

1. `result` **不得**进入 Decision Analysis 输入（规范第 28 节）
2. 案例**只能**用于相似检索 / 解释 / 训练 / 回归 / 红队样例（规范第 29 节）
3. **禁止**「找到类似牌就直接复制动作」（规范第 29 / 30 节）

## 3. 优先级裁决（规范第 39 节的可执行形式）

```
高  Math Truth                        ← 只能来自本项目确定性代码
    ↑
    Verified Individual Data          ← 该玩家的实测数据（置信度足够时）
    ↑
    Reliable Node-specific Data       ← 该节点的可靠数据
    ↑
    Game Environment Prior            ← 三种模式的方向性假设
    ↑
低  Generic Heuristic                 ← 通用启发式
```

### 冲突裁决示例

| 局面 | 环境先验说 | 个体数据说 | 裁决 |
|---|---|---|---|
| 河牌对手大额下注 | 低级别诈唬不足 → 倾向弃牌 | 该玩家实测河牌诈唬频率高且可信 | **采用个体数据**（加注/跟注） |
| 河牌对手大额下注 | 同上 | 该玩家只有 8 手样本 | **采用环境先验**（样本不足不覆盖） |
| 底池赔率要求 25% 权益 | 任何环境 | 任何玩家 | **数学说了算**，环境与个体都无法覆盖 |

## 4. 拒绝清单（明确不采纳）

| 项 | 原因 |
|---|---|
| GTOpen 的任何代码 / 文档 / 数据 | 无许可证 |
| 四本书的任何具体频率或结论 | 无正文 |
| 任何疑似盗版全文站点的内容 | 权利不明 + 违反版权 |
| 从被审计项目的求解器输出直接取参数 | 本项目未运行它们，无法独立复现 |
| 深筹码全范围实时求解 | 算力上与 1–3 秒目标不兼容（poker_solver 自己披露为分钟级） |
| 聚合器输出用于诈唬抓取结论 | 结构上回答不了该问题（poker_solver 明确论证） |
| 锦标赛策略用于现金 | Scope Audit 要求（尤其第 2 本书的书名同时覆盖两者） |
| 心理描述作为数学真值 | 规范第 12 节 |
