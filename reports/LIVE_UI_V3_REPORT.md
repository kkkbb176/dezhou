## 三、🔴 本轮从真实浏览器抓出的三个产品缺陷

### 缺陷 1：悬停画像掉回文档流底部（从 V2 甚至更早存在）

```js
showSeatTip(): tip.className = 'show';   // ← 把 seatTip 这个类整个换掉了
```

`position: fixed` 写在 `table.css` 的 `.seatTip` 规则里，类名一换就不匹配
⇒ `computed position = static` ⇒ `positionTip()` 设的 `left/top` **完全无效**
⇒ 提示框掉到文档末尾，铺成一条通栏文字条。

**实测证据**：`tipBox = { w: 1366, h: 39 }` —— 整个视口宽的一条文字，位于页面最底部。

**修法**：类名改成 `seatTip show`（保留定位所依赖的类），并且在 `positionTip()`
里**内联设置** `position/maxWidth/zIndex/pointerEvents` —— 提示框的定位不该由
「某个外来类名恰好没被覆盖」决定。

**修后实测**：`tipBox = { w: 360, h: 198 }`。

### 缺陷 2：座位 Pill 的「当前动作」与筹码**叠在一起**

V3 第一版把状态做成 `position: absolute` 的右下角标，实测它与 `.stack` 重叠 ——
截图里「99BB 投1BB」和「Hero」糊成一团，读不出来。

**修法**：筹码与当前动作放进**同一个 flex 行**（`.foot`），左筹码右动作，
永不重叠；`.status` 这个绝对定位类被彻底删掉。

**回归锁**：`V3-GRID-03` 断言 `.foot` 必须是 `flex` 且 `.foot .action` 不得有 `position`。

### 缺陷 3：右栏被压到 `#result` 只剩 14px，建议文字与按钮重叠

这是最严重的一个 —— 它让**最重要的信息「建议动作」不可读**。

**成因链**（逐层量出来的）：

1. 右栏做成「固定高度 + 四段按比例分配」，`#result` 是唯一的 `flex: 1 1 auto`；
2. 其它三段是 `flex: 0 0 auto`（不收缩），内容一多，**全部亏空由 `#result` 一家承担**；
3. 它没有内容下界 ⇒ 被压到 **14px**，而内容有 **174px**
   ⇒ 建议文字画在 14px 的盒子里，与下面的「重新分析」叠在一起。

推动它变高的三个具体原因（都逐一量过）：

| 原因 | 占高 | 处置 |
|---|---|---|
| 数据行 6 个键值对（含 3 项与中心区/座位 Pill 重复） | 107px | 只留 3 项 → **56px** |
| 快捷尺寸因「加注到 2BB」全写而折行 | 68px | 缩短文案 → **32px** |
| 「点加注展开合法尺寸」整行提示 | 21px | 删除 |

**结构性修法**：把「按比例分配」换成「**自然堆叠**」——
四段都 `flex: 0 0 auto` 各占需要的高度，`#rail` 用 `overflow-y: auto` 兜底。

**修后实测**：`#result = 174px`（内容 174px，无裁切），
`railScrollHeight = railClientHeight = 702`，**右栏无滚动条**。

### 缺陷 4（较轻）：命中「有请求在路上」时，界面**静默丢弃**点击

`post()` 在 `busy()` 时直接 `return null`（这是刻意的：牌桌操作没有幂等性，
并发提交会让「谁先到」决定最终状态）。但**什么都不发生**是错的表现方式 ——
使用者看到「点了没反应」，而真实原因是「后台正在跑 GTO 分析（实测 20+ 秒）」。

> ⚠️ **我自己就被它误导过一次**：V3 的浏览器验收里，翻牌之后板面第 4 张牌
> 点了十几次都上不去，看起来像「牌面录入坏了」。实际是那 20 秒里所有按钮都被禁用。
> 这条记在 `verify-live-ui-v3.ts` 的注释里。

**修法**：
1. 被丢弃时 `toast` **如实说明**（「正在分析，请稍候 —— 这一下没有提交」）；
2. 同步 `body[data-busy]`，样式表据此把主战况区画成半透明 + `cursor: progress`
   —— **在点之前**就看得出「现在不接受操作」；
3. **没有**解除操作锁（任务第八节明确禁止为表面提速而解锁）。

### 三个缺陷的回归锁

| 测试 | 锁住什么 |
|---|---|
| `test/liveUiV3.test.ts` · `V3-TIP-01` | 缺陷 1（静态锁：类名必须保留 + 定位必须内联设置） |
| `test/liveUiV3.test.ts` · `V3-GRID-03` | 缺陷 2（筹码与当前动作必须在同一 flex 行） |
| `test/liveUiV3.test.ts` · `V3-CSS-05` / `V3-GRID-01/02` | 「没有拟物椭圆牌桌」+「九个座位九个单元格且不占中心区」 |
| 浏览器验收 `v3-verify.json` | 缺陷 3（`railScrollHeight === railClientHeight`）+ 缺陷 4（`body[data-busy]`） |

## 七、诚实记录：`#rail` 的滚动策略

V3 期间最花时间的一处，值得写清楚。

右栏四段的内容高度**会随牌局变化**（建议文字长度、桌况面板是否出现、
快捷尺寸折几行）。实测最坏情况比可用高度多 **51px**。两种分配方式：

| 方案 | 后果 |
|---|---|
| 让 `#rail` 滚动 | 底部一整段（含「完整时间线」入口）从视野消失 |
| 让「最近行动」滚动（**已采用**） | 只影响最近行动的**可见条数**，其余全在 |

最终实测结果是**两者都不需要**：通过删除重复数据（数据行 6→3 项）、
删除冗余提示行、缩短快捷尺寸文案，自然高度降到 702px = 可用高度。

保留 `#rail { overflow-y: auto }` 与 `#recentActions { max-height: 96px; overflow-y: auto }`
作为**兜底**：如果将来某局的建议文字更长，损失只是「最近行动少显示一条」，
而不会让「建议动作」被压成 14px。
