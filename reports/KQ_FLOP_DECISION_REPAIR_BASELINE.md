### 2.1 D1 · 候选动作 EV 回填

**原缺陷**：`evaluateCandidates`（`decisionEngine.ts:605-618`）为**每一个**尺寸候选写死 `ev: null`，
注释写「下注的 EV 依赖对手弃牌率，本项目没有可信估计」。但证据层随后对**被选中的那个尺寸**
算出 `MODEL_EV` 并用它选了加注 ⇒ 同一响应里候选表与动作来源互相打架。

**修复方式（只回填，不重算、不改判）**：在 `pickCandidate` **之后**（`evidenceOut` 已填充处）

1. 从 `evidenceOut.raiseShape.raiseSizesWithOwnEV` 取「真正有自有可比 EV 的加注尺寸」；
2. **一致性闸**（用户 §五要求）—— 任一条件不满足即**拒绝回填**并给出原因：
   - 证据层登记的尺寸**恰好一个**（多于一个 ⇒ 无法确定金额与 EV 的对应 ⇒ 宁可不填，不猜）；
   - 金额必须是**整数筹码**（**不使用 `toFixed` 近似匹配**，杜绝串档）；
   - 候选层必须能匹配到**恰好一个**该金额；
   - 该候选原本 `ev === null`（不覆盖任何已有计算）；
3. 回填 `ev` 与新增的 `evEstimateType`（证据档位，如 `MODEL_EV`）。

**为什么不可能改变决策或置信度**：回填发生在 `pickCandidate` **之后**；
`confidenceOf` / `dynamicShadowOf` 读的是**重算之前**的 `mathDominance.evGapToPotRatio`。
已由 D0-a / D0-b 测试锁死。

**修正了上一轮首版的一处自身缺陷**：首版用
`candidatesWithEvaluatedEV === candidatesForDecision` 判断「是否回填过」——
而本节点未走 `betDecision` 补候选时两者**本来就是同一个对象**，该等式为真却与回填无关。
现改为显式判据（回填后存在加注 EV 且回填前不存在）。

### 2.2 D2 · 决策比较范围披露（四态）

**原缺陷**：静态标签 `DECISION_MARGIN_ZH.CLEAR_CALL_OVER_FOLD` 写死
「**仅**已证明 CALL > FOLD，**未比较加注**」；`mathDominanceOf` 的结论句也写死
「下注/加注 … **不在此比较之内**」。这两句都是**全局否定断言**，在加注 EV 确实参与
同一零点比较的节点上是**假的**（`decisionSource` 会同时报「跨动作比较已做」）。

**修复方式**：文案改为由**真实计算范围**生成，四态如实区分：

| 状态 | 含义 | 文案 |
|---|---|---|
| `NONE` | 未计算任何 RAISE EV | 「**未计算**任何加注尺寸的 EV」 |
| `SINGLE` | 只算了一个 | 「**只计算了 1 个**加注尺寸（正式候选共 N 个）—— **这不等于**已完成全部加注尺寸的 EV 比较」 |
| `PARTIAL` | 部分 | 「计算了**部分**加注尺寸（k / N）」 |
| `ALL` | 全部 | 「全部 N 个正式候选尺寸都已计算 EV」 |

判据完全来自**实际数组**（候选层加注族候选数 vs 其中 `ev !== null` 的个数），
不是靠文案常量声明。同时修正 `mathDominanceOf` 两处结论句，并新增
「未参与比较 ≠ EV 更低 / 未评估的尺寸不做低 EV 假设」的显式切断。

### 2.3 D3 · 人物画像标签语义

**原缺陷**：viewModel 用一行「标签」同时承担两个语义 —— 分类器推断（未判出时为
`UNKNOWN`）与「模型实际采用了什么」（说明行写「用户手选画像 AGGRESSIVE」）⇒ 并排读即矛盾。

**修复方式**：拆成两件事，**不篡改任何一边**：

- 行名改为「**推断标签（分类器）**」，值仍是分类器原样输出；
- 当分类器 `UNKNOWN` 而画像**实际生效**时，**就地**说明实际来源
  （数据取自已存在的 `profileRange.dimensionTier`，不新增任何推断）；
- 「说明」行保留（它才是「模型用了什么」）。

### 2.4 D4 · 统计项三态披露

**原缺陷**：`withMeasuredDisclosure` 的「本次进入模型」来自一张**硬编码两项**
（`foldToRiverBet` / `riverCheckRaise`）的清单 ⇒ 传入 `vpip` / `pfr` 时清单为空，
界面宣称「无（该玩家尚无模型支持的统计项）」—— 而这两个统计**确实改变了数值**。

**修复方式（三态 + 附加原因，判据只取真实执行路径）**：

状态由 `resolvedV3.trace` 与 `deniedStreetTraits` 推导，**不看字段名、不看用户输入、
也完全不看最终动作**（因此「动作没变 ⇒ 统计没进模型」这种误读在结构上不可能发生）：

| 判据（按序） | 状态 |
|---|---|
| 本次没有该键的数值 | `NO_DATA` |
| `trace` 里查不到该项 | `UNCONFIRMED`（**不默认 USED**） |
| 既无维度极性、也无分街条目 | `UNSUPPORTED` |
| 有效机会数 = 0 | `NO_DATA`（走先验） |
| 至少一条通道真实生效 | `USED` |
| 通道存在但全部被语义门挡下 | `NOT_APPLICABLE` |

披露同时给出：生效通道（维度 / 分街条目）、机会数、是否走「手数 × 频率」近似、
是否被先验收缩、后验可信度。

**两条独立通道都必须识别**（首版漏了第二条，把 `vpip`/`pfr` 误判为「模型无此通道」——
那句话是**错的**）：维度通道（`STAT_DIMENSION_POLARITY`，不受语义门约束）
与分街条目通道（受 `deniedStreetTraits` 约束）。

### 2.5 D5 · 决策边际说明

**原缺陷**：`decisionMargin` 只计算「跟注 EV vs 0 vs 容差带」这一条轴，`noteZh` 恒以
「真实跟注 EV = …」开头并以 `CLEAR_CALL_OVER_FOLD` 结尾 ⇒ 当最终动作是 RAISE 时，
这一行描述的是**另一个动作**。

**修复方式**（不动判据，只补事实）：

- 当最终动作自带量化 EV 且**不是** CALL 时，同一行内报出
  「最终动作 = 加注，其 `MODEL_EV` EV = 1948.14 筹码（同一零点、同一容差带）」，
  并显式声明「本行**不是**本次动作的判据，标签名只描述『跟注 vs 弃牌』这条轴」；
- 无论最终动作为何，都报出**加注 EV 覆盖面**（D2 四态）；
- **混合 EV 来源必须披露**：从证据表取实际来源集合，出现多于一种时声明
  「不同来源的模型假设与误差结构不同，跨来源比大小只在各自分辨力之内有意义；
  本引擎不声称它们严格同质」。

   「过牌-加注类不走这条通道」⇒ `traitStreet === null ⇒ return true`，
   即 check-raise 类条目**永不被语义门挡下**。实测状态为 `USED`，
   生效通道 = 分街条目 `flopCheckRaise`。
2. **「4% 与 25% 数值相同」的成因是收缩，不是无通道。**
   机会数 = `round(150 × 0.15) = 23`，而 `priorWeight = 200`
   ⇒ 后验可信度仅 `23/223 ≈ 0.103`，实测值被先验压得几乎不可见。

因此 D4 的正确性质**不是**「缺通道」，而是「**披露不实**」——即本轮修复的内容。
用户已确认的设计方向（三态披露、保留语义门、不新增重复通道）与这一更正**一致**。

**真正的 `NOT_APPLICABLE` 判据**来自 `actionContext.ts:187`：统计所属街 ≠ 当前街。

## 六·五、阶段二：多尺寸 EV 决策闭环（本轮新增）

### 6.5.1 改动方式（最小必要，不另写一份数学）

`contextBuilder.ts` 里「单个尺寸的全部计算」（资金台账 → `buildRaiseResponse` →
条件权益 → `raiseEVOf`）原本只对**一个**尺寸执行（`desiredTo = pot + 2×callCost`
吸附到最近档）。本轮把它**抽成一个闭包** `factsForRaiseTo(raiseTo)`，然后：

```
chosenFacts = factsForRaiseTo(被启发式选中的那一档)   ← 行为与修复前逐位一致
raiseResponseFactsAll = grid.map(o => factsForRaiseTo(o.toAmount))   ← 新增：网格内每一档
```

**关键设计**：网格内每一档都走**同一个闭包** ⇒ 公式、资金台账、响应模型、
容差带口径**逐位一致**，因此可以横向比较。**绝不为多尺寸另写一份数学**——
本仓库在 `contextBuilder.ts:4144` 已经踩过「两处口径不一致导致加注 EV 被静默关闭」。

### 6.5.2 黄金局面的逐尺寸评估结果（实测）

### 6.5.3 三个必须如实说出的结论

1. **8/8 尺寸已独立评估**（覆盖面四态由 `SINGLE` 变为 `ALL`），每档有自己的
   `P(弃)/P(跟)/P(再加注)`、条件权益、资金流与 EV；各档 EV **互不相同** ⇒
   证明不是把同一档的数字复制到别的金额（已由测试锁定）。
2. **启发式选中的 42BB 不是最高 EV**：最高是 **31.5BB（1968.58）**，高出 **20.44 筹码**。
   **但 20.44 ≪ 容差带 167.50**，且全部尺寸的极差仅 **110.78 筹码（< 167.50）**
   ⇒ **在本模型自己的分辨力之内，没有任何尺寸可以被证明优于其他尺寸**。
   因此本轮**不修改选尺寸规则** —— 换成 max-EV 等于把噪声当信号，
   也违背「不得为让软件更频繁加注/更容易盈利而调整模型」。
3. **不得声称任何尺寸是「全局最高 EV」**：模型未实现 4-bet 分支、非全下尺寸按
   **摊牌终止近似**、未计抽水、响应概率是未经统计校准的结构性先验。
   该声明连同四条具体理由已写进边际说明并被测试锁定。

### 6.5.4 本轮修正的一处**误标**（自我发现）

首版把**全下（97.5BB）**也标成了「近似计算」。这是**错的**：

## 六·六、阶段三：88% 弃牌率的可靠性审查与敏感性分析

### 6.6.1 生成机制（读出源码，非推测）

`src/app/manualInput/raiseResponse.ts:281-322`：

```text
price         = villainAdd / finalPot            ← 他自己的跟注赔率（数学确定）
required      = price + marginOfStreet(street)    ← margin：FLOP 0.16 / TURN 0.14 / RIVER 0.10
strength      = RAISE_RESPONSE_BAND_STRENGTH[band] + playability   ← **9 级离散阶梯**
continueIndex = strength × callScale − 0.05 × foldScale
继续 ⟺ continueIndex ≥ required ；否则把该组合的权重计入 foldMass
```

强度带常量（`raiseResponse.ts:76-86`，注释自述「**结构性阶梯**（只声称序关系），不是任何实测频率」）：
`NUT 0.97 / STRONG_MADE 0.86 / TWO_PAIR 0.72 / OVERPAIR 0.62 / TOP_PAIR_GOOD 0.52 /
TOP_PAIR_WEAK 0.40 / MIDDLE_PAIR 0.30 / WEAK_PAIR 0.20 / AIR 0.07`，
外加听牌可玩性 `+0.10`（强听）/`+0.05`（卡顺）。

### 6.6.2 关键结论：**P(弃) 是价格的「阶梯函数」，不是校准过的人群频率**

因为 `strength` 只取 9 个离散值，`P(弃)` 只在 `required` **跨过某个带的阈值**时才变化。
所以 **42/52.5/63/84BB 的 P(弃) 全等于 88.0%** —— 那几个尺寸的 `required` 落在同一个带间隙里。

### 6.6.3 第一性原理推导**逐档复现了引擎的实测值**（强验证）

| 尺寸 | price | required | 继续的带 | 引擎实测 P(弃) | 推导 |
|---:|---:|---:|---|---:|---|
| 24.5BB | 0.19266 | 0.35266 | + TOP_PAIR_GOOD | 76.7% | ✅ 一致 |
| 26.25BB | 0.21121 | 0.37121 | + TOP_PAIR_GOOD | 76.7% | ✅ 一致 |
| 31.5BB | 0.25547 | 0.41547 | + TOP_PAIR_GOOD | 76.7% | ✅ 一致 |
| **42BB** | 0.31285 | **0.47285** | **TOP_PAIR_GOOD 掉出** | **88.0%** | ✅ 一致 |
| 52.5BB | 0.34842 | 0.50842 | 同上 | 88.0% | ✅ 一致 |
| 63BB | 0.37262 | 0.53262 | 同上 | 88.0% | ✅ 一致 |
| 84BB | 0.40346 | 0.56346 | 同上（OVERPAIR 勉强继续） | 88.0% | ✅ 一致 |
| **97.5BB** | 0.41646 | **0.57646** | **OVERPAIR 也掉出** | **91.3%** | ✅ 一致 |

**8/8 全部复现，跳变点与引擎完全一致** ⇒ 88% 的来历已被完全解释，
它**不是**任何统计样本的产物。

### 6.6.4 脆弱性（fragility）：42BB 卡在 **0.00285** 的余量上

| 尺寸 | 临界带 | 阈值 | required | 余量 |
|---:|---|---:|---:|---:|
| 24.5BB | TOP_PAIR_WEAK | 0.350 | 0.35266 | **−0.00266** |
| **42BB** | **TOP_PAIR_GOOD** | **0.470** | **0.47285** | **−0.00285** |
| 84BB | OVERPAIR | 0.570 | 0.56346 | +0.00654 |
| 97.5BB | OVERPAIR | 0.570 | 0.57646 | −0.00646 |

**42BB 的 `required` 只比阈值高 0.00285（0.3%）。** 阈值再低 0.3%，整个
`TOP_PAIR_GOOD` 带就翻到「继续」，`P(弃)` 立刻掉 **11.3 个百分点**。
⇒ **88% 对模型常数极其敏感，不能当作稳定的对手读牌。**

### 6.6.5 各强度带的概率质量（由引擎实测跳变幅度反推）

| 跳变 | 幅度 | 归属 |
|---|---:|---|
| 76.7% → 88.0% | **11.3pp** | `TOP_PAIR_GOOD` ≈ 对手下注范围的 **11.3%** |
| 88.0% → 91.3% | **3.3pp** | `OVERPAIR` ≈ **3.3%** |

### 6.6.6 敏感性：**建议在什么参数区间会翻转**

`RAISE EV = f×pot + c×(eq×finalPot − contested) + rr×rrEV`，42BB 实测分解：
弃牌项 `0.88×2300 = +2024.00`、跟注项 `0.077×(−179.61) = −13.83`、再加注项 `−62.03`
（反解 `rrEV ≈ −1442.6`）。

```text
d(EV)/d(f) = pot − 跟注分支值 = 2300 − (−179.61) = 2479.61 筹码 / 单位 f
RAISE 相对 CALL 的优势                     = 303.62 筹码
⇒ 需要 P(弃) 下降 12.24 个百分点 才会翻转
⇒ 单个强度带 = 11.3pp ⇒ **一个带不足以翻转**（约需跨两个带）
```

**实测对照（引擎真实运行）**：`CALLING_STATION` 把 `P(弃)` 压到 **74.7%（−13.3pp）**，
RAISE 优势收窄到 **90.94 筹码** —— RAISE 仍胜出，但 **90.94 已落在 ±167.50 容差带之内**
⇒ **在该读牌下这个决定已变成掷硬币**，与解析区间（~12.2pp）量级完全吻合。

### 6.6.7 必须如实声明的限制

1. **88% 不是校准过的人群统计**：它是「9 级结构性阶梯 + 未校准阈值」的产物，
   源码注释本身就这么写。不得对外表述为「实测弃牌率」。
2. **各带权重是「由跳变幅度反推」而非逐组合枚举**：`betRangeEntries` 未对外暴露
   ⇒ 11.3% / 3.3% 是**差分推断**，精度受「相邻尺寸间其它因素恒定」约束。
3. **profile 敏感性里范围与响应层同时变化**（实测 `CALLING_STATION` 把
   「对手下注范围权益」从 80.43% 改成 78.46%）⇒ 74.7% 那个对照**不是纯响应层扰动**。
4. **高敏感性不等于模型错误**：阈值是工程先验，本项目从未声称已校准；
   但**必须**在披露里说清不确定性，不得展示为高置信度结论。

### 6.6.8 阶段三结论

> **88% 已完全解释**：它 = 「`strength − 0.05 < price + 0.16`」的几个离散带之和，
> 其中 `TOP_PAIR_GOOD`（11.3%）以 **0.00285** 的余量恰好落在门槛之外。
> 建议（RAISE 42BB）在 `P(弃)` 下降约 **12.2 个百分点**（≈ 跨两个强度带）时翻转；
> `CALLING_STATION` 实测（−13.3pp）使优势收窄到 90.94 —— **已进入容差带内**。
> 该结论**不需要也不包含**任何模型参数调整。
