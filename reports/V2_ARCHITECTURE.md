## 1. 第一性原理（系统宪法）

1. **目标不是赢下这一手，而是长期 EV 最大化。**
   必须严格区分：手牌胜率 / 当前权益 / 跟注所需权益 / EV / 决策质量 / 最终输赢。
   Hero 权益 35%、跟注只需 25% → 跟注仍可能是正 EV。系统不得因最后输了就判「跟注错误」。
2. **真人不是扑克机器人。**
   不能只用静态 GTO 范围表分析真人。系统执行：
   > **理论锚点 + 数学验证 + 动态真人模型 + Exploit 修正**
3. **GTO 提供锚点，真人行为决定偏移方向，扑克数学负责最终验算。**
4. **数学真值只能来自确定性代码。**
   LLM 允许：解释、表述、反驳。LLM 禁止：成为任何数字的来源。
5. **知道自己什么时候不知道。**
   样本不足 → 只给「初步迹象」；动作接近 → 标「边缘决策」；核心冲突 → 拒绝给建议。
6. **结果永远不能反向污染决策评价。**
   「当时决策分析」与「摊牌后分析」在数据结构层面物理隔离。

### 依赖规则（架构级硬约束）

- **单向依赖**：上层可读下层，下层绝不引用上层。
- **数学不可被覆盖**：`agents/mathAuditor` 的结论是只读真值，任何 Agent 不得修改。
- **动态模型只能改概率**：动态行为引擎的输出**只能**影响范围权重与频率，不得直接产生动作。
- **UI 只读 ViewModel**：UI 层不得包含任何策略判断逻辑。
- **中文只从 i18n 出**：领域层只输出码值，UI 层只做映射。

| 中文词条层 | `src/i18n/**` | 唯一文案出口，i18n → domain 单向 |

**已固化的不变量**（都有测试）

1. 一副牌恰好 52 张且互不重复。
2. 筹码守恒：`Σ起始 == Σ(剩余 + 前注 + 各街投入)`。
3. 底池恒等于账本合计（唯一数据源）。
4. 行动顺序：翻牌前枪口位先、大盲最后；翻牌后小盲先、庄家最后。
5. 短全下加注不重开加注权（TDA）。
6. 两种牌力引擎的强度编码逐位相同。
7. 精确枚举局数 = 组合数 × C(剩余牌数, 待发牌数)。
8. 非法输入一律拦截，绝不静默纠正。

## 4. 状态检查器（层 ②，V1 已交付）

**职责**：所有输入合法性。**任何策略计算之前必须先过这一层。**

覆盖：重复牌、桌型人数、位置、行动顺序、Stack、Pot、Call Size、Raise Size、

- 版本一致性检查（决策日志中的各引擎版本）

## 5. 数学引擎（层 ③，V1 已交付）

**职责**：Equity / Pot Odds / Required Equity / EV / SPR / Outs / Bet Size / Stack。

**硬约束**

- 全部由确定性程序计算；**LLM 不得成为数学真值来源**。
- 优先精确枚举；组合过大转蒙特卡洛；**必须记录模拟次数、随机种子、误差范围**。
- 算不了就返回「暂时无法准确计算权益」，**绝不编造数字**。

**输出口径**（UI 必须一致）

```
当前权益：43.2%
计算方式：蒙特卡洛
模拟次数：500,000
估计误差：±0.3%
最低所需权益：25.0%
数学判断：允许跟注
```

## 6. 范围引擎（层 ④，V2 新增）

### 6.1 两层结构

```
第一层：理论基础范围
  输入：位置、桌型、有效筹码、前面动作、下注大小、人数
  输出：组合 → 基础权重（0..1）

第二层：针对性修正
  输入：玩家画像 + 动态状态 + 桌面动态
  输出：组合 → 修正后权重
```

### 6.2 逐街贝叶斯式更新（核心）

**不预测「他一定是什么牌」，而是更新「各种牌出现的概率」。**

```
P(手牌 | 动作序列) ∝ P(动作序列 | 手牌) × P(手牌 | 位置, 筹码深度)
```

实现形态（V2 采用加权组合更新，不引入完整 CFR）：

1. 每个组合携带一个权重 `w ∈ [0, 1]`。
2. 对手每做一个动作，用「该组合执行此动作的频率」乘到权重上。
3. 频率表由「理论基线频率」×「玩家类型修正」×「动态状态修正」共同决定。
4. 归一化后得到当前范围分布。

**示例**：翻牌前 20% → 翻牌跟注后缩窄 → 转牌加注后再缩窄 → 河牌超池后再重权重。

### 6.3 强制约束

- 频率只能修改**概率**，不得写成绝对规则。
  - 禁止：`紧手 = 一定有大牌`、`松手 = 一定在诈唬`。
  - 允许：`紧弱型枪口位加注 → 强牌组合权重显著提高`。
- 每次更新必须记录「更新前 / 更新后」的组合权重，供复盘展示。
- 范围必须经过状态检查器的覆盖度校验，空范围直接触发 Fail Safe。

## 7. 玩家模型（层 ⑤，V2 新增）

### 7.1 底层是连续数据，标签只是概括

覆盖指标：翻牌前入池倾向、主动加注倾向、3Bet、4Bet、跟注、弃牌、C-bet、
Fold to C-bet、Turn aggression、River aggression、River bluff、River call、
Check-raise、Overbet、Showdown。

**标签**（紧弱 / 紧凶 / 松弱 / 松凶 / 跟注站 / 诈唬偏多 / 诈唬偏少 /
超级紧手 / 普通常客 / 强常客 / 未知）只是**概括**，底层永远保存连续数据。
标签可以变，连续数据不会因为标签变化而丢失。

### 7.2 样本置信度（三层）

| 层级 | 样本量 | 允许的表达 |
|---|---|---|
| 低 | < 30 手 | 「初步倾向：偏松」「样本量：8」「可信度：低」 |
| 中 | 30 ~ 200 手 | 「倾向：偏松」「可信度：中」 |
| 高 | > 200 手（且关键指标样本 ≥ 30） | 「玩家画像：松凶型」「可信度：高」 |

**禁止**：观察 8 手就写「这是松凶玩家」。

### 7.3 时间衰减

```
权重 = 2^(-Δhands / 半衰期)     半衰期默认 400 手
```

- 300 手以前的行为与最近 20 手的行为**权重必须不同**。
- **但禁止**：最近一手行为直接推翻长期画像。
  单次行为对画像的影响必须被上限约束。

> ⚠️ **实现中的一个诚实说明（Step 6 交付时确认）**
>
> 规范原文写「单手上限 ≈ 总权重的 1~3%」。但这条约束在数学上有一个硬边界：
> n 手**均匀**权重时单手占比恒为 `1/n`，这是任何权重分配下的**理论下界**。
> 因此当 `总权重 5% < 1/n`（即 `n > 20`）时，「单手 ≤ 总权重 5%」**不可满足**。
>
> 实测：半衰期 400 手时，601 手历史里最新一手的占比只有约 **0.27%** ——
> 远低于 5%，上限对一个健康分布施加的是无意义的约束。
>
> 当前实现取「相对均匀权重的倍数」口径：`实际上限 = maxShare × n`。两个性质同时成立：
> - 均匀权重**永不触发**（无谓的信息损失为零）
> - 病态集中（599 手权重 1 + 单手权重 500，占比 45%）**必然触发**
>
> 该口径差异已登记为风险 K7，Step 7 复核。两种口径的行为差异都有测试锁定。

### 7.4 Step 6 已交付的实现结构

| 文件 | 职责 |
|---|---|
| `player/player.types.ts` | 25 项指标定义（含中文机会 / 成功规则）、先验表、`MetricStat`（**分子分母同时保存**） |
| `player/playerStats.ts` | 时间衰减、单手影响上限、Kish 有效样本量、置信度、Beta-Binomial 收缩、样本分层 |
| `player/playerProfile.ts` | 事件驱动增量画像、幂等、修正历史、全量重算、**逐层**深冻结 |
| `player/playerClassifier.ts` | 连续维度（紧度 / 凶度 / 诈唬倾向 / 被动度）、11 种中文标签、有界调整因子 |
| `handPotential.ts` | 启发式手牌潜力标尺（**明确声明不是胜率**，只用于比较强弱） |
| `range/profileProvider.ts` | 画像 → 范围引擎的**唯一**连接点（实现 `RangeAdjustmentProvider`） |

**四条硬约束的落地**：

1. **机会由牌局状态定义，绝不由玩家动作定义** —— 否则「从不诈唬的人」会因为
   「他从没诈唬过」而永远不被计入诈唬机会，**分母被他的行为偷走了**。
2. **每项指标独立分母** —— 500 手总样本 ≠ 河牌超池样本 500。无机会时
   `rawRate = null` 而**不是 0**。
3. **先验来源透明** —— 类型上只有 `HEURISTIC_PRIOR` / `TEST_PRIOR` /
   `UNKNOWN_PRIOR` / `EMPIRICAL_PRIOR`。`THEORY_PRIOR` / `GTO_PRIOR`
   **在类型系统里就不存在**。
4. **画像绝不直接决策** —— 三重断言强制：结构（输出对象键名不得含动作语义）、
   类型（`ProfileAdjustment` 只有 `number` 字段）、模块（桥接不导出任何
   牌力 / 赔率 API）。

**中心化原则**：调整因子做**几何均值归一**，使画像只改变概率分布的**形状**
而非整体尺度 —— 一致放大在归一化后会被抵消，属于无意义操作。

### 7.5 牌局环境（Step 6.5 交付）

同一个动作在不同牌局环境里含义不同：低级别线上局对手跟注更多、诈唬更少、
位置意识更弱；理论参考模式下我们只关心「对手被视为理性且平衡时应该怎么打」。
若不区分环境，「对手加注 = 强牌」这条推断在低级别局里会系统性偏错。

| 模式 | 中文名 | 调整方向 |
|---|---|---|
| `LOW_STAKES_ONLINE` | 低级别线上 | 范围更宽、诈唬更少、更被动、河牌更保守、弱牌端倾斜更大 |
| `MID_LOW_STAKES` | 中低级别（**默认**） | 全部因子恰为 1 |
| `THEORY_REFERENCE` | 理论参考 | 范围更窄、诈唬占比更高、更凶、弱牌端收窄 |

**硬约束**：环境**只允许**改 Range 先验 / 动作似然 / 决策阈值，
**绝对不允许**改牌力、底池、筹码、SPR、底池赔率、所需权益。
这一点用三重断言锁定（源码 import 扫描 + 模块导出扫描 + 行为 `deepEqual` 对照）。

**为什么必须有「端倾斜」（`weakEndTilt` / `strongEndTilt`）**：
因子集合会被几何均值归一，而单纯缩放整体宽窄（`rangeWidth`）正是归一化
要消掉的东西 —— 实测只调 `rangeWidth` 时，三种环境对弱牌的影响差异不足 2%，
功能形同虚设。端倾斜作用于范围**内部形状**，是归一化无法抵消的通道。

**数值来源**：**没有**任何可靠的分级别人口统计数据。所有调整都是
**相对**的启发式倍数（1 = 不调整），强度限制在 ±25% 以内，每一项都标注
`HEURISTIC` 来源并带版本号。一旦拿到真实数据，只需替换 profile 对象，
调用方代码零改动 —— 这就是「不得散落 if/else」的落地方式。

⚠️ `THEORY_REFERENCE` 不得在界面上称为「GTO 最优」：本项目**没有求解器输出**，
这里的「理论」是**结构性假设**（平衡、无系统性漏洞），不是求解器结果。
这句话写在配置的中文描述里，并有测试断言它必须存在。

## 8. 动态行为引擎（层 ⑥，V2 新增）

### 8.1 动态真人状态

正常 / 谨慎 / 明显变紧 / 明显变松 / 高攻击性 / 追损倾向 / Tilt 可能 /
赢后放松 / 怕被诈唬 / 过度保护筹码 / 异常激进 / 异常被动 / UNKNOWN。

### 8.2 状态是概率，不是结论

- **禁止**：某人刚输一个大底池 → 直接 `Tilt = TRUE`。
- **必须**：`Tilt 概率 = 25%`，随后根据证据继续提高或降低：
  - 连续超池 → 提高
  - 异常 3Bet → 提高
  - 范围突然扩大 → 提高
  - 快速 Call → 提高
  - 异常全下 → 提高
  - 随后恢复正常开池尺寸 → 降低

### 8.3 行为偏移指数（0–100）

衡量「当前打法距离该玩家自己的长期正常打法有多远」。

```
偏移指数 = w1·|PFR_recent − PFR_long| / PFR_long
         + w2·|3Bet_recent − 3Bet_long| / 3Bet_long
         + w3·|OpenSize_recent − OpenSize_long| / OpenSize_long
         + ...
         （各分量先做上下限截断，再加权归一化到 0..100）
```

示例：长期 PFR 18%、最近 20 手 42%；长期 3Bet 6%、最近 18%；
长期平均开池 2.5BB、最近 5BB → **行为偏移指数 72 / 100，状态：明显异常**。

### 8.4 异常下注检测

玩家过去平均开池 2.5BB，突然 Open 8BB：
- **不能**直接说「8BB 一定是 AA」。
- **应该**输出「异常程度：高」，并同时调整：价值范围概率 ↑、诈唬范围概率 ↑、随机赌博行为概率 ↑。

### 8.5 红队约束（规范第四十四节）

| 场景 | 必须的行为 |
|---|---|
| 玩家只有 3 手数据 | 禁止给出任何画像结论，只能「未知玩家」 |
| 长期 Nit，最近 1 手 All-in bluff | 禁止「玩家变成疯子」；偏移指数只允许小幅上升 |
| 连续 20 手异常 | 才允许明显提升行为偏移指数 |
| 刚输一个大底池 | 只允许给出 Tilt 概率，不得直接判定 Tilt |

## 9. Exploit 引擎（层 ⑦，V2 新增）

**职责**：回答「应该如何针对」。

**输入**：理论基线范围 + 玩家画像 + 动态状态 + 桌面动态
**输出**：偏移后的频率表（价值频率 / 诈唬频率 / 弃牌频率 / 跟注频率）

典型映射（只改概率）：

| 对手特征 | 偏移方向 |
|---|---|
| 诈唬偏少 | 增加弃牌（尤其是抓诈唬场景） |
| 跟注站 | 减少诈唬，增加价值下注尺寸与频率 |
| 超级紧手 | 减少对其诈唬，尊重其加注 |
| 松凶型 | 收紧跟注范围，增加反击频率 |
| 追损倾向（概率高） | 放宽价值下注范围，减少诈唬 |

**三种策略模式**

| 模式 | 说明 |
|---|---|
| 理论模式 | 接近理论基线，不做针对性调整 |
| 针对模式 | 根据玩家特点明显调整 |
| **混合模式（默认）** | 理论基线 + 玩家针对（中低级别、部分玩家很紧、部分偏松的典型环境） |

## 10. 决策引擎（层 ⑧，V2 新增）

**职责**：产出候选动作 + 尺寸 + 置信度。

### 10.1 混合模式管线

```
① 理论基线          → 各动作的理论频率
② 玩家画像调整      → 长期倾向偏移
③ 动态行为调整      → 短期状态偏移
④ 桌面动态调整      → 最近 10/20/50 手的事件影响
⑤ 数学验证          → 用 EV / 最低所需权益 / SPR 做最终验算与裁剪
```

**顺序不可颠倒**：数学永远是最后一道闸门。

### 10.2 输出结构

```ts
type DecisionOutput = {
  action: ActionType;              // 主建议
  size?: { ratio: number; amount: number; labelKey: string };  // 必须带具体尺寸
  confidence: { level: ConfidenceLevelCode; value: number; reasons: ConfidenceReason[] };
  decisionTypeKey: MessageKey;     // 抓诈唬 / 价值下注 / 针对性弃牌 ...
  isMarginal: boolean;             // 边缘决策
  alternatives: Array<{ action: ActionType; probability: number; ev: number }>;
  theoryBaselineKey: MessageKey;   // 理论基线：接近边界 / 明显偏离
  playerAdjustmentKey?: MessageKey;
  dynamicAdjustmentKey?: MessageKey;
  mathGate: EquityGate;            // 数学闸门结果（只读真值）
  version: VersionStamp;           // 各引擎版本
};
```

### 10.3 边缘决策与禁止假装唯一答案

- `Call EV` 与 `Fold EV` 差距小于阈值 → 必须显示「**边缘决策**」并同时列出两个选项：
  ```
  跟注：54%
  弃牌：46%
  边缘决策
  ```
- **禁止**输出「100% CALL」这类伪确定性结论。

### 10.4 多人池独立逻辑

人数增加后必须整体调整（**禁止直接套用 Heads-Up 模型**）：

| 人数增加 | 调整 |
|---|---|
| 价值下注门槛 | 提高 |
| 纯诈唬频率 | 下降 |
| 边缘牌价值 | 下降 |
| 顶对价值 | 下降 |
| 加注范围 | 偏强 |
| 抓诈唬范围 | 缩紧 |
| 界面显示 | 必须明确「当前：4人底池」 |

## 11. 多智能体对抗审查（层 ⑨，V2 新增）

### 11.1 八个角色

| # | 角色 | 职责 | 明确禁止 |
|---|---|---|---|
| 1 | 数学审计员 | 权益、EV、底池赔率、SPR、赔率、下注大小 | 不得加入「感觉他很强」 |
| 2 | 范围分析师 | Value Combos、Bluff Combos、Draws、Range Advantage、Nut Advantage | 不得做最终裁决 |
| 3 | 玩家画像分析师 | 长期玩家类型 | 样本不足时不得下结论 |
| 4 | 动态行为分析师 | 最近行为、Tilt 概率、追损、攻击性变化、异常下注、行为偏移 | 不得直接判定 Tilt = TRUE |
| 5 | Exploit 分析师 | 应该如何针对 | 不得越过数学闸门 |
| 6 | **反方审查员** | **必须攻击当前最佳建议** | 不得偷懒附和 |
| 7 | **墨菲审计员** | 专找输入 Bug / 逻辑 Bug / 样本 Bug / 范围 Bug / 结果导向 / 过拟合 / 多人池错误 | 不得只说「没问题」 |
| 8 | 最终裁判 | 综合全部结果输出最终建议 | **不得修改确定性数学结果** |

### 11.2 反方审查员（强制反驳）

| 主建议 | 必须回答 |
|---|---|
| 跟注 | 为什么**弃牌**可能更好？ |
| 弃牌 | 为什么**跟注**可能更好？ |
| 下注 | **过牌**是不是更好？ |

缺少反驳字段时，该决策视为**不合法输出**，由墨菲审计员拦截。

### 11.3 禁止简单投票

- **禁止**：5 个 Agent 说 Call、3 个说 Fold → 所以 Call。
- **必须**按职责加权：
  - 数学审计员的**数学结果不可被情绪类 Agent 推翻**。
  - 动态行为 Agent 的输出**只能修改范围概率**，不能直接改变动作。
  - 严重冲突 → **降低置信度**并显式列出分歧点，而不是取平均抹平。

### 11.4 Fail Safe（规范第四十六节）

出现以下任一情况，必须输出「**当前无法给出可靠建议**」：

- 核心数据冲突（重复牌、账本不守恒）
- 数学错误（除以零、溢出、NaN）
- 范围无法建立（空范围、覆盖度不足）
- 关键 Stack 缺失
- Agent 严重冲突且无法归因
- Equity 计算失败

**绝不允许**为了给答案而输出未经验证的建议。

## 12. 复盘引擎（层 ⑩，V2 新增）

### 12.1 每手牌保存字段

牌局ID、日期、游戏级别、桌型、盲注、有效筹码、位置、Hero 手牌、Board、
完整行动、Opponent Model、Dynamic Human State、System Recommendation、
Hero Actual Action、Equity、Pot Odds、EV、Confidence、Final Result、Showdown。

### 12.2 两种复盘必须物理分离

| 分析类型 | 允许使用的信息 | 数据结构 |
|---|---|---|
| **当时决策分析** | 只能用当时已知信息 | `DecisionContext`（对手手牌为 null） |
| **摊牌后分析** | 允许使用真实对手手牌 | `ShowdownContext` |

**禁止**：最后发现对手是 66，就倒推「所以河牌当然应该跟注」。
必须根据当时的**整个合理范围**重新判断。

实现约束：`DecisionContext` 中不存在「对手真实手牌」这个字段，
从类型层面杜绝结果污染。

### 12.3 EV 错误报告（不只看输赢）

```
第 128 手
Hero River Call
系统建议：弃牌
估计 EV 损失：−14.2BB
```

长期排序依据是 **Expected EV Loss**，不是「输钱最多」。
这样长期才能判断真正的漏洞。

## 19. 合规红线（架构上不留接口）

**不做**：自动读取线上扑克客户端、自动屏幕识别实时牌桌、自动点击下注、
自动替用户操作、绕过第三方平台规则、隐蔽实时覆盖层、自动代打。

系统定位始终是：**训练 + 复盘 + 决策研究**。
