## 1. 审计方法：为什么必须成对构造场景

第一轮的 55 项单元测试之所以没抓到缺陷，原因是一个**结构性盲区**：

> 那些测试几乎全部断言「**不该报警时别报警**」
> —— 与基线一致 → NORMAL、样本不足 → UNKNOWN、非法输入 → Fail Closed。
>
> **没有一条断言「该报警时必须报警」。**

因此第一轮的纪律是：**每个场景都必须写成「对照 + 异常」对**，
并断言两者的**关系**（而不只是各自的性质）：

```
对照：数据完全符合基线         → 要求 score 低、无信号
异常：数据真实偏离基线         → 要求 score 显著上升、状态正确翻转
断言：异常.score − 对照.score ≥ 阈值    ← 这一条才是关键
```

第二轮（独立）用的是**完全不同的方法**，因而能发现第一轮漏掉的东西：

| 方法 | 发现了什么 |
|---|---|
| **批量确定性种子统计**（400 个 LCG 种子，真值 = 基线） | 误报率随历史长度从 12% 升到 **51%**（F3）；虚假冲突提示 0.3% → **30%**（F3） |
| **同一 VPIP 曲线、只改变「记了几项指标」** | 追加**真实且强相关**的证据反而把正确判决换成错误判决（F1） |
| **源码级死代码扫描** | `SIZING` 组无指标映射 → `SIZE_ANOMALY` 永不可达；`MAX_SINGLE_EVENT_SHARE` 改不动任何输出（F5 / F11） |
| **契约一致性矩阵**（asOf / 脏数据 / 上下文 / Hint 全组合） | 别人的损失抬高本人 Tilt（F6）；畸形输入 TypeError 崩溃（F8）；`asOf = NaN` 让未来事件全进（F9） |
| **性能规模扫描到 10000 事件** | 5000 事件 P95 **突破预算**（F12）；比较器内 `Date.parse` |

## 2. 缺陷清单

### 2.1 第一轮（作者自查，5 项）

#### D1（CRITICAL）收缩强度取基线样本量 → 20 手窗口信号被完全压平

**位置**：`dynamicStats.ts` → `computeWindowStats`

**错误写法**：

```ts
const k = baselineStat ? Math.max(0, baselineStat.effectiveSampleSize) : 0;
```

`k` 是「个人基线被当作多少次观测的先验」。取基线自身的等效样本量，
意味着一个 400 手（甚至 1000 手）的基线会以 400 份先验权重，
去压制 20 手窗口里的 20 次观测。

**实测后果**：

| 场景 | 真实数据 | 系统输出 |
|---|---|---|
| 对照 | VPIP 15%（与基线一致） | score = **0** |
| 异常 | VPIP **15% → 45%**（20 手 9/20） | score = **1**，状态 `NORMAL` |

`adjustedRate` 被算成 0.1745（真值 0.45），偏差只有 2.45 个百分点。

**为什么危险**：使用者看到 `NORMAL` 会按原范围应对，
而对手的入池频率已经**三倍化**。

**修正**：收缩强度只由**近期观测数**决定。

**中途的错误尝试（诚实记录）**：第一次修正只把 `k` 改成常数上界
`min(基线 ESS, 40)`，score 从 1 升到 **21**，仍然偏低。
此时才意识到根因是**概念混淆**：
「基线有多长」与「近期证据有多强」是**两件无关的事**。

---

#### D2（CRITICAL）同一 `confidence` 被连乘三次 → 信号再砍到 1/4

**位置**：`dynamicDeviation.ts` → `aggregateGroup`；`dynamicBehavior.ts` → `deriveAdjustments`

**错误写法**：

```ts
// aggregateGroup：用 strength × confidence 挑冠军，并把乘积累进 score
const weighted = deviation.strength * deviation.confidence;
// deriveAdjustments：再乘一次
const weightOf = (state) => probabilityOf(state) * input.confidence;
```

而 `probabilityOf` 本身已经由 `groupSignal` 从**置信度加权的组分数**推出。

**实测后果**：一个 20 次机会、变化幅度 30 个百分点的玩家，
最终权重只剩 `0.45 × 0.5 × 0.5 ≈ 0.11`，方向调整被**静默丢弃**。

**为什么这是概念错误**：`deviationScore` 的语义是「**他偏离了自己多少**」，
不是「**我有多确定他偏离了**」。两者必须**分开输出**。

**修正**：`aggregateGroup` 取 `strength` 的最大值；`deriveAdjustments` 不再乘置信度。

---

#### D3（CRITICAL）置信度刻度错位 → 远超门槛的样本只得 0.5 可信度

**错误写法**：

```ts
const recentConfidence = effectiveSample / (effectiveSample + MIN_BASELINE_OPPORTUNITIES);
```

分母用了**基线**门槛（20），而正确的参照是**判断门槛**
（`MIN_RECENT_OPPORTUNITIES` = 8）。

**修正**：按机会数在 `[判断门槛, 充分]` 上线性映射。

---

#### D4（MAJOR）方向判定用绝对阈值 → 输出**虚假方向冲突**提示

**错误写法**：

```ts
const direction = Math.abs(delta) < 0.01 ? 'NONE' : delta > 0 ? 'HIGHER' : 'LOWER';
```

**实测后果**（对一个**完全正常**的玩家）：

```
conflicts: [ '开池加注下降但 3Bet 上升 —— 进攻性变化方向不一致' ]
```

它来自 20 次机会下的 ±1 次计数差。

**修正**：按两比例差的标准误检验。

---

#### D5（MAJOR）方向检验的样本量取错 → **漏掉**真实冲突

**错误**：用 20 手**窗口内**的计数估计方差。
「窗口」只是取样本的**位置**，不改变**样本量**。

**修正**：改用全部近期事件的机会数。
（第二轮 F3 又证明这个修正本身也有问题 —— 见 F3。）

### 2.2 第二轮（独立红队，3 CRITICAL + 9 MAJOR + 3 MINOR）

#### F1（CRITICAL）最经典的偏离被判反，且输出自相矛盾

**最小复现**（40 手，基线 VPIP 15% / PFR 12% / 3Bet 7%，近期 36/40、0/40、0/40）：

```
修复前：dominantState = AGGRESSION_DOWN   deviationScore = 19
        adjustments = [AGGRESSION_LIKELIHOOD DECREASE, FOLD_LIKELIHOOD INCREASE 1.2523]
        → 没有任何 RANGE_WIDTH 调整；反而输出「更可能弃牌」
```

同一 VPIP 曲线、**只不记 PFR/3Bet** → `LOOSER_RECENTLY, 26 分, RANGE_WIDTH ×1.2316`。
⇒ **追加两条真实且强相关的证据，把正确判决换成了错误判决。**

**机理**：`aggregateGroup` 在组内方向冲突时判 `NONE`，
而兜底分支的条件是 `entry.direction === 'HIGHER'` ——
**它专为的那个冲突下永不可达**。

**修正**：组方向取**主导方向**（偏移更强者），新增 `directionContested` 标记。

**修复后**：`LOOSER_RECENTLY`、32 分、`RANGE_WIDTH INCREASE ×1.2316`、
并提示「更可能是被动跟注变多」。

#### F2（CRITICAL）充分性与 confidence 由「跨指标机会总数」决定

- `MIN_RECENT_OPPORTUNITIES = 8` 比较的是所有指标机会**之和**：
  1 手牌声明 8 个机会即脱离 UNKNOWN，而每项指标可能只有 0~1 次观测。
- confidence 样本项用总数：**真值 = 基线的玩家，2 手 → 0.900，20 手 → 0.851**
  —— **置信度随样本增加而下降**，且 2 手牌就能拿到满额 1.2523× 范围因子。

**修正**（两处）：
1. **充分性**要求**至少一项指标自身**达到门槛；
2. **置信度**样本项用「可比指标中**最小**的机会数」。

**修复后**：1~3 手 → `UNKNOWN`、0 分、无调整，
解释文本明确写出「最多的一项仅 N 次，合计 M 次分散在多项指标上」。

#### F3（CRITICAL）方向检验与强度用了不同样本量 → 判决随手数翻转

真实率恒为 25%、基线 VPIP 15%：

```
 n     W20 raw  W20机会  W20 adjusted   ENTRY方向  状态             分数
 40     0.25      20     0.240001        NONE    NORMAL            5
 60     0.25      20     0.240001        NONE    NORMAL            5
 80     0.25      20     0.240001      HIGHER    LOOSER_RECENTLY   9
100/200  同上（窗口统计逐位相同）        HIGHER    LOOSER_RECENTLY   9
```

⇒ **快照公布的数字复算不出 `direction`**；误报率随历史长度
从 12.3% 升到 **50.7%**，虚假冲突提示从 0.3% 升到 **30.0%**。

**修正**：方向检验的样本量**固定为窗口机会数**，使 `direction` 可由快照字段完全复算。

**修复后**（400 种子）：误报率 20 手 17.3% → 200 手 14.2%，**不再随历史增长**。

#### F4（MAJOR）deviationScore 无零假设刻度

真值 = 基线时（20 手、400 种子）：均值 **19.82**、P95 **35**、MAX 49；
**12.0%** 的数据集拿到非 NORMAL + 上限幅度。

**修正**：引入 **z 检验门槛** —— 强度不再只是「有界归一化差值」，
而是「**显著且幅度大**」：

```
z        = |rawRate − baselineRate| / SE      （标准两比例检验）
显著性   = clamp01((z − 1.5) / (2.6 − 1.5))   // z ≤ 1.5 → 0
strength = 效应量 × 显著性
```

**修复后**：均值 **8.0**、P95 **22**。

> **这一条费了最多轮次（诚实记录）**：先后试了 5 种组合才定下来 ——
> - `k = 基线样本量` → 假阴性（0 分）
> - `k = min(基线 ESS, 40)` → 21 分，仍偏低
> - `k = (REF−c)/c` → 41 分，但误报 36.5%
> - z 门槛 2 / 斜坡终点 4 → 真实大变化只有 **7 分** ❌
> - **z 门槛 1.5 / 斜坡终点 2.6 + 温和收缩 `k = c/3`** → ✅ 两者兼顾
>
> 关键认识：**压制噪声与压制真实变化是同一条曲线**。
> 想让误报降到 0，只需把收缩加到无穷大，代价是永远发现不了任何变化。
> 正确分工是「收缩温和抑制极端值 + 显著性检验区分噪声与真实变化」。

**统计学要点（已写进代码注释）**：
- 方差估计**不能用观测率**：观测 0/20 时 `p̂(1−p̂) = 0` → 边界陷阱（误报 36.5%）
- 也**不能用零假设率**：基线远离 0/1 时方差偏大 → 真实变化被压到 12 分
- **正解是 Wilson 修正**：`(p̂(1−p̂) + 1/(4n)) / n`
- 基线侧方差**必须用基线自身样本量**：用窗口 n 等于宣称「基线只有 20 次观测」，
  会把基线噪声放大 `√(n₂/n₁)` 倍（400 手基线 → 4.5 倍）

#### F5（MAJOR）「尺寸异常」是死代码；12 个真实指标不参与偏差

## 5. 元层教训

### 5.1 「测试全绿」可以完全掩盖假阴性

**12 条 CRITICAL/MAJOR** 全部在 55/55 单元测试通过时存在。
根因不是测试写得少，而是**测试的断言方向单一**。

**永久措施**：红队场景必须**成对**写，`test/dynamicBehaviorRedTeam.test.ts`
的每个编号场景都包含正常对照与真实异常，并断言两者的**差值**。

### 5.2 单靠「自己再检查一遍」发现不了方法盲区

第二轮用**完全不同的方法**（批量种子统计、边界扫描、源码死代码检查），
立刻发现了第一轮 5 项修复之后仍然存在的 3 个 CRITICAL。
**作者自查与独立审计不可互相替代。**

### 5.3 参数调不对时，先怀疑概念而不是继续调参

F4 花了 5 轮才定下来。前 3 轮都在「调数字」，直到意识到：
- 「基线有多长」与「近期证据有多强」无关（不是参数问题，是概念问题）
- 「压制噪声」与「压制真实变化」是同一条曲线（不是取舍问题，是分工问题）

### 5.4 同一个量被多次使用时要数清次数

`confidence` 在链条上被用了三次。每一次单独看都「有道理」，
叠起来就把信号压没了。**规则**：一个量在一条链上出现多于一次时，
必须明确每次的**不同职责**。

### 5.5 文档里的公式必须能被测试复算

F11 指出收缩公式与文档注释**差 c 倍**。文档写错的公式比没有公式更危险 ——
它会让下一个读者以为保护比实际强。**凡写进注释的公式，都要能被快照字段复算。**

### 5.6 我自己的两处错误（诚实记录）

1. **红队测试的布尔生成公式写错**：`(i+1)·r ≥ ⌊i·r⌋ + 1` 在 `i = 0` 时恒为假，
   使所有指标在第 0 手被记为失败，实际速率系统性偏离目标值。
   影响面仅限测试构造，但让第一轮的一个场景失真。
2. **修 D1 时先按「基线样本量」调参**（把常数 40 当成上界），得到 21 分仍偏低，
   才意识到根因是概念混淆而非参数取值。
