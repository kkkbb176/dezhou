# Alpha 内部测试版 —— 使用说明

> **仅供内部个人使用。** 本文件说明如何启动与使用这个内部决策参考工具。

---

## 1. 启动

### 推荐：双击启动器

```text
scripts\start-alpha.cmd
```

它会自动做三件事：

1. 已经在运行 → 直接打开浏览器，不重复启动
2. 没在运行 → 在**独立窗口**里启动服务（关掉启动器不影响服务）
3. **等到服务真的能访问之后**再打开浏览器（不做假承诺）

**停止**：双击 `scripts\stop-alpha.cmd`
（它只杀监听该端口的进程，不会误伤 GTOpen 求解器）

### 等价的命令行方式

```powershell
cd D:\德州
node.exe --experimental-strip-types "src/app/webServer.ts"
```

⚠️ 这个方式要求**终端窗口一直开着** —— 关掉窗口服务就停了。
这正是「网页打不开」最常见的原因。

### 打开地址

**http://127.0.0.1:5173**

- 只监听 `127.0.0.1`（**不对外开放**，无账户、无云同步、无遥测）
- 换端口：先 `set ALPHA_PORT=8080`，再双击启动器（或 `$env:ALPHA_PORT=8080` 后跑命令行）
- 健康检查：`http://127.0.0.1:5173/api/health`
- GTO 范围页：`http://127.0.0.1:5173/gto`

### 不开网页也能用

```powershell
node.exe --experimental-strip-types "scripts/alpha-demo.ts"
```

会打印一手示例牌的完整建议与全部诊断。

## 2. 怎么录入

> 🔴 **界面已经改成「交互式牌桌点选」**（点座位 / 点牌面 / 点行动），
> 不再需要键盘填表。牌桌的操作方式见 **`docs/TABLE_INPUT_USAGE.md`**。
>
> 下面 §2.1–§2.4 描述的是**输入语义**（金额口径、行动顺序、筹码含义）——
> 它同时适用于两种情况：
>
> 1. 牌桌上的按钮（后端按同一套语义生成）
> 2. API 的 `POST /api/analyze` 之 `{ "input": … }` 入口（旧表单路径保留，仍是公开契约）

### 2.1 输入包含什么

| 字段 | 说明 |
|---|---|
| 桌型 | 6 人桌 / 9 人桌 |
| Hero 位置 | 位置中文（括号内是英文缩写） |
| Hero 手牌 | 两张，如 `As` `Kd` |
| 当前街道 | 翻牌前（0 张公共牌）/ 翻牌（3）/ 转牌（4）/ 河牌（5） |
| 公共牌 | 按顺序，空格分隔。翻牌如 `Kh 7c 2d` |
| 有效筹码 | 单位 BB |
| 行动历史 | 每行一条 |

**牌面格式**：点数 `2-9 / T / J / Q / K / A` + 花色 `s h d c`（大小写不限）。
`As` = 黑桃 A，`Td` = 方块 10。

### 2.2 底池（可选）

**留空即可** —— 系统会按行动记录重算。

只有当你**确认**自己记的底池是对的、并想借此检查行动记录时，才填它。
填了就必须与重算结果一致，否则**系统会阻断分析**（这是刻意的：
不允许「先按填写的底池算」）。

### 2.3 行动历史（最容易填错的一项）

格式：`位置 动作 [金额BB] [街道]`

```
UTG FOLD
HJ FOLD
CO RAISE 3
BTN FOLD
SB FOLD
BB CALL 2
BB CHECK FLOP
```

**金额的语义**（关键）：

| 动作 | 金额含义 |
|---|---|
| `RAISE` / `BET` | **加注到**的本街总额（不是「加了多少」） |
| `CALL` | **本次投入**的金额 |
| `ALL_IN` | **可选**。填 = 必须等于该对手的**全部剩余筹码**；**留空 = 投入全部剩余筹码**（推荐） |
| `CHECK` / `FOLD` | 不需要金额 |

> **全下怎么填**（短筹码对手是最常见的局面之一）：
> 1. 在右栏填「**对手筹码（BB）**」，例如 `8`
> 2. 行动行写 `UTG ALL_IN`（**不用填金额**）
>
> 若填了金额但对不上他的剩余筹码，系统会阻断并明确告诉你两种改法 ——
> 不会猜、也不会静默按你写的数字算。

**街道**可以省略（继承上一条）。跨街时**必须**写，或者按顺序写清楚：

```
CO RAISE 3          ← 翻牌前
BB CALL 2           ← 翻牌前
BB CHECK FLOP       ← 翻牌（必须写 FLOP）
CO BET 2.5 FLOP
BB CALL 2.5 FLOP
BB CHECK TURN       ← 转牌
```

**不需要填盲注**（小盲/大盲由系统自动下）。

**行动顺序**（6 人桌）：
- 翻牌前：`UTG → HJ → CO → BTN → SB → BB`（大盲最后）
- 翻牌后：`SB → BB → UTG → HJ → CO → BTN`（**小盲先**，庄家最后）

> 顺序填错会被阻断并提示「应该轮到谁」——不会静默纠正。

### 2.4 对手与环境

- **环境**：只提供**方向**参考，**不会**修改底池/赔率/权益
- **快速画像**：你的主观判断，可信度上限 0.35；有实测数据时以实测为准
- **近期观察**：只用于调整**置信度**，不会翻转明确决策。
  **观察到偏离**才会降低置信度；填「打法正常」与留空得到**相同**的置信度
  （填表不该被惩罚）
- **对手筹码（BB）**：留空 = 所有对手与你的有效筹码相同。
  **短筹码对手**（全下、浅筹码对抗）必须填这里，否则系统会按 100BB 处理
- **大盲筹码面额**（`bigBlindBB`，界面暂未暴露）：表示「1BB 等于多少筹码」，
  必须是**不小于 2 的整数**（默认 100）。只影响筹码数字的显示口径，
  **不影响**底池赔率 / 所需权益 / SPR / 权益这些无量纲判断。
  填小数会被阻断而不是取整 —— 系统不会替你改数字

### 2.5 最快上手

牌桌界面上：**点空座位 → 「加入玩家」**（一次性），然后每一手只需
**点两张手牌 → 按当前行动者点行动 → 轮到 Hero 时点「分析当前决策」**。
典型每手 9 次点击。详见 `docs/TABLE_INPUT_USAGE.md`。

## 3. 怎么读结果

首屏给出四件事：

```
建议：下注
尺寸：3.25BB（325 筹码）
置信度：中低
类型：边缘决策

核心原因：
· 对对手范围估计权益 89.6% 且明显领先，当前牌力（顶对 K，A踢脚）适合主动下注取值
· 牌局环境「中低级别」提供了 1 条方向参考（无幅度，仅方向）
· 抽水模型：未计入（本项目尚无 Rake Engine，EV 为未计抽水口径）
```

**类型**的三个含义：

| 类型 | 含义 |
|---|---|
| **明确决策** | 数学上分离度大，可以放心执行 |
| **边缘决策** | 接近临界，执行但不要把金额敏感度调高 |
| **信息不足** | **系统拒绝编答案** —— 关键输入缺失或范围塌缩 |

**「信息不足」时不要强行决策。** 系统宁可说不知道，也不给一个看起来自信的错建议。

### 调试区（可折叠）

点开可以看每一层的原始数据：数学九项 / 对手范围（含组合数与更新轨迹）/
玩家画像 / 环境方向 / 动态行为 / 数学优势保护 / 动态 Shadow 对比 / 耗时 / 版本。

**这些值就是引擎实际使用的值**，没有任何加工。

## 4. 已知限制（务必先读）

| 限制 | 说明 |
|---|---|
| **尚未用真实牌局验证** | 目前只通过了内部烟测与红队，**没有**实盘校准 |
| 范围是**启发式先验** | 不是求解器输出、不是 GTO 范围；可信度 0.3 |
| **抽水未计入** | 所有 EV 都是未计抽水口径（`Rake model: NOT_APPLIED`）；不显示 bb/100 |
| 下注/加注的 **EV 不参与比较** | 缺可信的对手弃牌率估计；因此「加注 vs 跟注」是**定性**判断 |
| **≥3 名活跃对手** | 明确返回「信息不足」，**不会**假装单挑 |
| **2 名活跃对手是近似** | 权益只按**单挑口径**估算（只针对首要对手），第二家的行动**未进入模型** → 结果**偏乐观**，界面会明确显示这条警告 |
| 翻牌前范围较粗 | 只有「开池范围」/「面对开池的继续范围」/「3Bet 范围」三档；防守范围把跟注与再加注合并建模 |
| 范围更新是**单调启发式** | 只表达「强牌更可能主动下注」这类方向，不是实测频率 |
| 不支持 | 3 名以上活跃对手的多人池 / 锦标赛 / 短牌 / Rake / 自然语言输入 |

**不要用本工具做**：自动读牌、自动点击、任何形式的自动打牌。
它只是一个手动输入后的参考。

## 5. 发现明显错误怎么办

这是内部测试版，**最有价值的反馈就是「一眼就明显错误」的建议**。

记录时请一并记下：

1. 完整输入（表单内容）
2. 系统给出的 Action / Size / 置信度 / 类型
3. 核心原因原文
4. 你期望是什么，以及为什么
5. 错误属于哪一层（看调试区：Input / Validator / Math / Range / Profile /
   Environment / Dynamic / Decision / Size / Confidence / UI）

**建议先记下判断，再看摊牌结果** —— 否则会陷入结果导向。

### 决策日志

每次分析都会追加一条到 `data/decision-log.jsonl`，包含：
输入哈希 / 引擎重算底池 / 环境 / 决策 / 置信度 / 各模块版本 / 各阶段耗时 / 抽水口径。

它**不含**对手底牌，也**不含**结果 —— 这是刻意的（结果不得进入决策链）。

**「信息不足」在日志里记为 `decision: null`**，而不是 `"FOLD"` ——
否则「系统拒绝给建议」与「系统建议弃牌」在机器可读字段里无法区分。
