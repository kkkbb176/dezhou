# 知识政策 —— 来源优先级与使用纪律

> **本文件是规范文本**（一手证据）。知识库中的规则
> `internal.spec-priority` 与 `internal.environment-priors` **引用本文件**作为出处。
>
> 本文件只规定**裁决顺序与使用纪律**，不提供任何数值参数。

---

## 1. 知识优先级链（冲突时的裁决顺序）

当不同来源对同一局面给出不同结论时，**必须**按下列顺序裁决，高优先级**覆盖**低优先级：

```
① Math Truth                        ← 只能来自本项目自己的确定性代码
      ↓ 覆盖
② Verified Individual Data          ← 该玩家的实测数据，且置信度达标
      ↓ 覆盖
③ Reliable Node-specific Data       ← 该节点类型上的可靠数据（位置 × 街道 × 人数）
      ↓ 覆盖
④ Game Environment Prior            ← 三种牌局环境的方向性假设
      ↓ 覆盖
⑤ Generic Heuristic                 ← 通用启发式（"大家都这么说"）
```

### 1.1 每一层的定义与门槛

| 层 | 名称 | 什么是 | 什么不是 | 门槛 |
|---|---|---|---|---|
| ① | **Math Truth** | Hand Rank / Pot Odds / Equity / EV / Combinations / Blocker 的计算结果 | 任何外部资料的观点 | 必须由本项目确定性代码产出且可复现 |
| ② | **Verified Individual Data** | 该玩家的实测指标（`PlayerProfile`） | 泛化的牌池统计 | **有效样本量**达标（不是原始机会数）|
| ③ | **Reliable Node-specific Data** | 该节点类型（位置 × 街道 × 人数 × 筹码）上的聚合数据 | 跨节点的平均 | 需要按节点分桶统计 |
| ④ | **Game Environment Prior** | `LOW_STAKES_ONLINE` / `MID_LOW_STAKES` / `THEORY_REFERENCE` 的方向性假设 | 精确频率 | 只能给方向；无数据时 `magnitude` 必须缺省 |
| ⑤ | **Generic Heuristic** | 通用启发式规则 | 有数据支撑的结论 | 只能作为待验证假设 |

### 1.2 裁决的三条硬规则

1. **高层覆盖低层，但不静默**。覆盖必须留下可审计记录（哪两条冲突、依据什么覆盖）。
2. **样本不足不构成覆盖资格**。第 ② 层要覆盖第 ④ 层，其**有效样本量**必须达标 ——
   8 手数据不得推翻环境先验。
3. **第 ① 层永不被覆盖**。任何层级的调整都不得改变牌力、底池、筹码、SPR、
   底池赔率、所需权益或权益算法本身。

## 2. 证据等级（Evidence Level）

来源按可复核程度分四级，**规则自身声明的等级不得高于其来源中的最高等级**：

| 等级 | 定义 |
|---|---|
| `PRIMARY` | 一手证据：原始数据、求解器输出、规范文本、可复现实验 |
| `VERIFIED_SECONDARY` | 经独立复核的二手证据：有方法与样本量、可追溯原始数据 |
| `SECONDARY` | 二手证据：有出处但无法独立复核原始数据 |
| `HEURISTIC` | 启发式：依据公认原理构造，无数据支撑 |

**规范文本（如本文件、项目规范）属于 `PRIMARY`** —— 它就是本项目必须遵守的规则本身。
但它**不产生数值参数**。

## 3. 量化数据的两级区分

来源的量化数据必须区分两个**完全不同**的问题：

| 字段 | 问题 | 作用 |
|---|---|---|
| `hasQuantitativeData` | 「这份来源里**有**数字吗？」 | 仅用于说明来源性质 |
| `derivableQuantitativeData` | 「我们能拿这些数字**定参数**吗？」 | **只有它为 `true` 时，规则才允许带 `magnitude`** |

### 3.1 「有数据但取不到」的四种典型情形

1. **无许可证**：数据权利不明，不得取用
2. **数据在上游、来源未确认**：即使代码是宽松许可，数据本身的权利仍需单独核实
3. **数据是被审计项目的求解器输出**：本项目未运行该求解器，无法独立复现
4. **无可复现路径**：只存在于其内部流水线

### 3.2 让一个来源变成「可推导」的路径（**不是唯一的**）

> ⚠️ **本节在 Phase 4.5 首轮曾写成「转为 `true` 的唯一合法路径是真实牌局校准」——
> 那是一个过于绝对的表述，会把未来的路自己堵死。现已更正。**

`derivableQuantitativeData` 是**一个门槛，不是一条路径**。任何满足下列全部条件的来源
都可以把该字段置为 `true`：

| # | 条件 | 说明 |
|---|---|---|
| 1 | **来源与许可证清晰** | 门禁为 GREEN，或已获得明确授权；数据本身的权利（不只是代码）已核实 |
| 2 | **场景匹配** | 游戏类型（现金/锦标赛）、人数（HU/6-max/9-max）、筹码深度、抽水结构与我们使用它的场景一致 |
| 3 | **可在本地独立复现** | 我们能在自己的机器上重跑并得到一致结果（求解器输出需满足此条），或数据本身可核验 |
| 4 | **经过交叉验证** | 至少有一个独立实现/独立数据集的对照，或满足 §3.3 的验证门 |

**三条已知的合法路径**（未来还会有别的）：

| 路径 | 现状 | 缺什么 |
|---|---|---|
| **A. 内部真实牌局数据统计** | ✅ **当前唯一已经可执行的路径** | 需要牌局数据积累 |
| **B. 可授权、可追溯、场景匹配的统计数据集** | ⬜ 尚未找到 | 需要同时满足上述 4 个条件的数据源（Phase 4.5 审计的四个项目都不满足） |
| **C. 能在本地独立复现并经过交叉验证的 Solver 输出** | ⬜ 尚未具备 | 需要第二实现 + 算力 + 许可证评估（见 `SOLVER_CROSS_VALIDATION_PLAN.md`） |

> **准确的表述**是：
> **在当前项目条件下，内部真实牌局数据是目前唯一*已经可执行*的量化校准路径；
> 未来经过来源、许可证、复现与交叉验证的数据同样可以进入。**
>
> 这不是文字游戏 —— 差别在于：前者是一个**可执行清单**，
> 后者是一个**封闭断言**；封闭断言会在条件变化后变成错误的约束。

### 3.3 magnitude 的硬校验

**`magnitude` 的唯一合法依据是 `derivableQuantitativeData: true` 的来源。**
没有它时，规则只允许给方向（`INCREASE` / `DECREASE` / `CONTEXT_DEPENDENT`），
`magnitude` **必须缺省**。这不是建议，是硬校验（`validateStrategyKnowledge`）。

> 注意区分两句话：
> - 「**依据**必须是可推导来源」—— 这是**门槛**，永远成立（§3.3）
> - 「**路径**只有真实牌局校准」—— 这是**路径**，**不成立**（§3.2）

## 4. 环境不得覆盖数学（硬约束）

无论 `LOW_STAKES_ONLINE` / `MID_LOW_STAKES` / `THEORY_REFERENCE` 中的哪一种，
下列**永远不变**：

- 底池、筹码、SPR
- 底池赔率、所需权益
- 牌力大小、权益算法

环境**只允许**影响：范围先验、动作似然、决策阈值。

**落地方式**（三重断言，均有测试）：

1. **源码扫描**：`gameEnvironment.ts` 的 import 行不得含
   `handEval` / `fastEval` / `equity` / `odds` / `gameState` / `engine` / `validator`
2. **导出扫描**：该模块的导出名不得含
   `evaluate` / `equity` / `potOdds` / `requiredEquity` / `handRank` / `spr` / `callEV`
3. **行为对照**：遍历三种环境，用 `deepEqual` 断言
   `potOdds` / `requiredEquityForBet` / `spr` / `callEV` 返回值逐位相同，
   并用真实牌力引擎断言牌力评估结果不变

## 5. 理论模式不是「完美 GTO」

`THEORY_REFERENCE` 只有在**同时满足**下列两个条件时，才允许在界面上显示
`Solver Reference`：

1. 有**可靠求解器输出**
2. **场景抽象匹配**（人数、筹码深度、下注尺寸菜单、抽水结构均一致）

否则只能显示 **「理论参考」**，且**绝不允许**显示「GTO 最优」。

**本项目当前状态**：没有任何求解器输出。因此 `THEORY_REFERENCE` 是
**结构性平衡假设**（平衡、无系统性漏洞），且其配置的中文描述中已写明
「本项目**没有求解器输出** …… 不是求解器输出，不得在界面上称为 GTO 最优」
（有测试断言这句话必须存在）。

## 6. 许可证门禁

| 门禁 | 许可证类型 | 允许 |
|---|---|---|
| `GREEN` | MIT / Apache-2.0 / BSD-2/3-Clause / ISC / 0BSD / Unlicense / CC0 / MIT-0，以及**项目自有内容** | 满足许可证条件时可借鉴或移植 |
| `YELLOW` | GPL / AGPL / LGPL / MPL / **CC-BY-SA**（带 ShareAlike 的 copyleft） | 默认**只研究思想**，未经明确评估禁止复制代码 |
| `RED` | 无许可证 / 权利不明 / 非商业 / 禁止演绎 | 只研究概念，**禁止复制** |

### 6.1 保守默认

**未知一律 `RED`。** 把「不知道」当成「可以用」是本项目最不能犯的错误。

### 6.2 门禁由许可证**推导**，不接受手写

JSON 中的 `licenseGate` 字段**会被解析器忽略并覆盖**。
这样即使有人手写一个更宽松的门禁，也无法绕过。

## 7. 外部数据不得直接污染生产

所有新来源 / 新范围 / 新案例必须先进 **`QUARANTINE`**，
通过下列全部检查后才能进入 **`VERIFIED`**：

1. schema validation
2. provenance validation
3. license audit
4. regression test
5. red-team

---

## 8. Fail-Closed

若出现下列任一情况：

- 策略模型不存在
- 策略数据损坏
- hash 不一致
- 验证失败
- 来源未知

则**不生成假的策略**，显示「当前缺少可靠策略基线」，
而**不是**自动创建一个看起来专业的答案。

**落地位置**：

| 位置 | 机制 |
|---|---|
| 知识库加载 | `loadKnowledgeBaseOrThrow` 校验失败即抛错，不返回部分索引 |
| 范围归一化 | 不用绝对阈值判坍塌（否则会静默伪造「范围为空」） |
| 权益计算 | 显式拒绝而非静默降级（不允许静默升格迭代数） |
| 玩家画像 | 样本不足 → 标签强制「未知玩家」+ 全部调整因子恒为 1 |
| 牌局环境 | 未登记的环境名**抛错**，不回退默认 |
