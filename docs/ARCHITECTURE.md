# 德州扑克决策与复盘训练系统 V1 —— 架构与实施规划

> 版本：V1.0（阶段 1 起）
> 适用范围：无限注德州扑克（NLHE）现金局，6 人桌 / 9 人桌
> 使用方式：手动录入牌局 → 牌后分析 → 训练 → 模拟 → 复盘
> **明确不做**：读取第三方客户端、识别在线牌桌、自动点击下注、代替玩家操作、绕过平台规则。

---

## 0. 第一性原理（本项目的宪法）

1. **目标不是提高单手牌胜率，而是最大化长期期望收益（EV）。**
   「获胜概率」与「最佳决策」是两个不同的量。摊牌权益 35%、最低所需权益 25% 时，跟注是正确的正 EV 决策。
2. **结果 ≠ 决策质量。**
   - 赢了不代表决策对（结果好 ≠ 打得好）。
   - 输了不代表决策错（结果差 ≠ 打得差）。
   - 系统对每一手牌**分别输出两个独立评分**：决策质量、结果质量。
3. **确定性计算与语言模型严格分工。**
   牌力、听牌张数、底池赔率、最低所需权益、底池筹码比、权益、EV —— 全部由确定性程序枚举/模拟得出。语言模型**只允许**做解释、表述、情景假设与反驳，**绝对禁止**心算或编造数字。
   无法计算时输出「暂时无法准确计算权益」，不猜测。
4. **知道自己什么时候不知道。**
   信息不足 → 降低置信度；样本不足 → 只给「初步迹象」；动作接近 → 标注「边缘决策」；核心冲突 → 拒绝给建议。
5. **优先级：正确性 > 易用性 > 界面美观 > 功能数量。**

**设计决定**：中文显示按「桌型 + 座位序号」解析，而非仅按内部键。

### 3.3 行动顺序（已用属性测试锁定）

- **翻牌前**：UTG → UTG+1 → UTG+2 → 低劫持 → 劫持 → 关煞 → 庄家 → 小盲 → 大盲 →（回到 UTG）
  即庄家的下一位开始，大盲最后行动。
- **翻牌/转牌/河牌**：小盲 → 大盲 → UTG → … → 庄家。
- **单挑（只剩 2 人）**：
  - 翻牌前：庄家 = 小盲，先行动；大盲后行动。
  - 翻牌后：大盲先行动，庄家后行动。（V1 用「小盲位先行动」的通用规则，在单挑下自然退化为大盲先行动）
- 位置数量必须与桌型严格匹配：6 人桌恰好 6 个位置，9 人桌恰好 9 个。

## 4. 数据模型

### 4.1 值对象（强类型，构造即校验）

```
Rank        2..9, T, J, Q, K, A                    （内部码 2..14）
Suit        SPADES | HEARTS | DIAMONDS | CLUBS
Card        { rank, suit }  唯一标识 "As" / "Td" / "7c" / "2h"
Position    UTG|UTG1|UTG2|LJ|HJ|CO|BTN|SB|BB
Street      PREFLOP | FLOP | TURN | RIVER
ActionType  FOLD|CHECK|CALL|BET|RAISE|RERAISE|ALL_IN|POST_SB|POST_BB|POST_ANTE|REVEAL|SHOWDOWN|STRADDLE
TableSize   6 | 9
PlayerId    string（稳定不变）
```

不变量（构造函数内强制，违反即抛 `Error` + 可翻译的 `MessageCode`）：
- `Card` 的 rank 必须在 2..14，suit 必须是 4 种之一。
- 花色只能是单一字符 `s/h/d/c`；点数只能是 2..9/T/J/Q/K/A。
- 严格解析：`"1s"`、`"Asx"`、`"X"` 一律失败，**不做猜测式纠正**。

### 4.2 牌局状态

```
GameConfig  { tableSize, smallBlind, bigBlind, ante, currencyUnit }
Player      { id, name, seat, position, startingStack, remainingStack,
              committedByStreet{PREFLOP,FLOP,TURN,RIVER},
              folded, allIn, revealedHoleCards, playerType,
              observedStats{hands, vpip, pfr, threeBet, ...} }
Board       { flop:Card[3], turn:Card[1], river:Card[1] }   ← 分街存放，禁止混堆
ActionRecord{ index, street, playerId, position, type, amount, toAmount,
              isAllIn, potBefore, potAfter, timestamp }
GameState   { id, config, players, board, actions, userPlayerId,
              street, currentBet, lastRaiseSize, lastAggressorId,
              pendingActionQueue, pot, rake, notes, createdAt }
```

### 4.3 账本不变量（每条都有对应测试）

1. **筹码守恒**：`Σ(remainingStack + ΣcommittedByStreet) == ΣstartingStack`（无抽水时）。
2. **底池 = 所有街已投入之和**：`pot == Σ_allPlayers Σ_allStreets committed`。
3. **单街合法性**：任一玩家单街投入 ≤ 其起始筹码；`committed` 不为负。
4. **有效筹码** = `min(用户剩余筹码, 主要对手剩余筹码)`（按街起点或当前剩余，明确标注口径）。
5. **底池不为负**，**筹码不为负**，**下注不超过持有筹码**（超过即非法，除非标记全下）。
6. **跟注金额 = min(当前注额 − 我已投入, 我剩余筹码)**；差额不足即为全下跟注。
7. **最小加注** = 上一次加注增量（翻牌前初始为 1 个大盲）；全下不足最小加注时不重开加注权。

## 6. 自动化测试计划

### 6.1 测试层次

| 层次 | 手段 | 目标 |
|---|---|---|
| 单元测试 | `node:test` | 每个纯函数的正常路径 |
| 边界测试 | 手写极端用例 | 空牌、4 张翻牌、全下、零筹码、A2345 |
| 属性测试 | 随机 + 固定种子，1000 次以上 | 不变量永真（牌唯一、筹码守恒、顺序合法） |
| 回归测试 | 每个已修 Bug 固化一条用例 | Bug 不复活 |
| 黄金用例 | 手工核对的经典牌局 | 端到端结果与人工计算一致 |

### 6.2 必测清单（对应规范第 45 条）

**牌与重复检查**
- [x] 一个牌堆恰好 52 张且互不重复
- [x] 同点数同花色 → 重复牌冲突
- [x] 同点数不同花色 → 合法
- [x] 用户手牌 vs 公共牌重复
- [x] 用户手牌 vs 已知对手手牌重复
- [x] 翻牌 3 张相同花色点数不同 → 合法
- [x] 公共牌 5 张全同花色 → 合法（同花面）

**牌型引擎**
- [x] 9 种牌型全部识别
- [x] A2345 小顺（含 5 张与 7 张两种情况）
- [x] 皇家顺子结构 = A 高同花顺
- [x] 踢脚比较：同为一对、同为两对
- [x] 公共牌就是最佳五张（双方都用公共牌 → 平分）
- [x] 平分底池（完全相同的五张）
- [x] 公共牌成顺（打牌面顺子）
- [x] 公共牌成同花
- [x] 两对公共牌 + 踢脚决定胜负
- [x] 三条 / 葫芦 / 四条的正确识别与比较
- [x] 反超与被反超（转牌领先 → 河牌被反超）
- [x] 同花顺 vs 四条 vs 葫芦 的相对强度

## 7. 可能出现的 Bug（已预判并已在代码中设防）

| # | 潜在 Bug | 后果 | 设防措施 |
|---|---|---|---|
| B1 | `String.replace` 只替换第一个花色字符，`"Asd"` 被解析成 As | 静默认错牌 | 用严格正则 `^([2-9TJQKA])([shdc])$`，不做替换式纠正 |
| B2 | 大小写混用 `"aS"` 被拒绝或误判 | 用户输入体验差 / 认错 | 先 `toLowerCase` 再严格匹配 |
| B3 | 10 用 `"10"` 表示，与 `"1"+"0"` 混淆 | 认错牌 | 只接受 `T`；显式拒绝 `"10s"` 并提示用 `T` |
| B4 | 7 张牌评估只取「出现次数最多的牌型」 | 漏掉同花顺、漏掉葫芦 | 同花检测优先级最高，且以 5 张同花组成的顺子为准 |
| B5 | A2345 轮子顺判断错误（A 既当高又当低） | 顺子判错 | 专用 8192 项查表，A 仅在 `A2345` 中当低 |
| B6 | 踢脚取错（两对时误取公共牌上更大的无关牌） | 平分/胜负判错 | 踢脚从「**排除这两个对子点数**后的最高牌」取，且严格降序打包。⚠️ **2026-09 修正**：此前这里写的是「只从『不在成对点数中』的最高牌取」，那条口径**本身是错的** —— 7 张出现**三个对子**时（`Q Q T T 8 8 3`），第三个对子的 8 **可以**作踢脚（最佳五张 `Q Q T T 8`）；从「未成对点数」取会得到 `Q Q T T 3`。旧口径让 25% 的 `(2,2,2,1)` 型 7 张编码错误，实测 20 万次摊牌有 82 次判错胜负 |
| B7 | 四条时踢脚取成四条本身的点数 | 比较错误 | 踢脚显式排除四条的 rank |
| B8 | 葫芦比较时先比三条还是先比对子搞反 | 比较错误 | 编码顺序固定为「三条在前、对子在后」 |
| B9 | 牌力编码溢出导致比较失真 | 静默错误 | 编码上限约 1.2e10 << 2^53，安全；有专门测试断言 |
| B10 | 底池重复计入盲注（盲注既算 committed 又额外加进 pot） | 底池虚高 | 底池**只**由 `committed` 求和得出，单一数据源 |

| B16 | 有效筹码按起始筹码而非当前剩余计算 | 深度判断错误 | 明确口径：按当前剩余计算，函数注释写死 |
| B17 | 浮点权益百分比导致 0.1+0.2 类误差 | 显示 42.000000001% | 权益内部用整数计数（胜/平/负次数），显示时才转百分比 |

| B20 | 多人底池沿用单挑逻辑 | 系统性错误 | 所有数学函数入参为 `opponentCount`，≥3 时走多人分支并显式标注「当前：N人底池」 |

## 8. 墨菲定律风险清单

> 会出错的地方一定会出错。以下每一项都对应代码里的具体防线。

### 8.1 输入侧

| 风险 | 现实场景 | 防线 |
|---|---|---|
| M1 牌被认错 | 语音说「方牌九」被识别成方块9，实际是梅花9 | 严格解析 + 不确定即要求确认 + 界面对每张牌显示「图案+中文」冗余 |
| M2 重复牌 | 公共牌已有 7♦，对手手牌又填 7♦ | 检查器全局唯一性校验，冲突即阻止分析 |
| M3 翻牌填了 4 张 | 手滑多点一张 | 结构校验：翻牌必须恰好 3 张，且第 4 张必须报错而非忽略 |
| M4 筹码填成 0 或负 | 忘记填 | 缺失即报「影响决策的筹码信息缺失」，不猜测 |
| M5 底池手填与行动记录不符 | 用户凭记忆填 100,000，实际 92,000 | 重算 + 差异提示（金额与差额都显示），禁止静默忽略 |
| M6 位置数量与桌型不符 | 9 人桌只填了 6 个人 | 明确报错，不自动补人 |
| M7 大小盲写反 | 盲注 2000/1000 | 校验 `smallBlind < bigBlind`，且必须整除关系合理 |
| M8 动作顺序跳人 | 直接从枪口位跳到庄家位 | 行动顺序校验，报「未轮到该玩家行动」 |

### 8.2 计算侧

| 风险 | 现实场景 | 防线 |
|---|---|---|
| M9 权益被编造 | 语言模型「感觉你有 65%」 | 架构上语言模型拿不到计算权，只能引用 `EquityResult`；无结果时输出「暂时无法准确计算权益」 |
| M10 权益算错 | 枚举漏掉某些组合 | 精确枚举与蒙特卡洛交叉验证测试（偏差 > 1.5% 即失败） |
| M11 底池漂移 | 撤销一步后底池没回滚 | 全量重算，不做增量修补 |
| M12 有效筹码算错 | 用了起始筹码 | 函数只接受当前剩余筹码；口径写在函数名与注释里 |
| M13 多人池当单挑 | 4 人池沿用单挑阈值 | `opponentCount` 强制入参，≥3 走多人分支并标注 |
| M14 数学异常被吞 | 除以 0 得到 Infinity 直接输出 | 所有除法检查分母，异常即 `MATH_ERROR` → 「当前无法给出可靠打法」 |

### 8.3 结论侧

| 风险 | 现实场景 | 防线 |
|---|---|---|
| M15 结果导向 | 因为赢了就说打得好 | 决策质量与结果质量**分字段存储、分字段渲染**，物理上无法互相污染 |
| M16 事后诸葛亮 | 看到对手是 66，反推河牌当然该跟 | 复盘强制两段式：`当时决策分析`（只用当时信息）/ `摊牌后分析`（可用真实手牌），数据结构分离 |
| M17 确认偏差 | 系统只找支持自己结论的证据 | 智能体 4（反方审查员）强制输出反对理由，缺字段即校验失败 |
| M18 小样本贴标签 | 8 次河牌跟注就下「严重过宽」结论 | 样本量保护：< 30 次输出「初步迹象 + 当前样本 N + 样本不足」 |
| M19 置信度虚高 | 信息不全却给 95% 置信度 | 置信度由输入完整度、范围确定度、样本量、EV 差距、智能体一致度、未知信息量**六项加权**得出，任一项缺失即封顶 |
| M20 强行给唯一答案 | 跟注 52% / 弃牌 48% 却说「必须跟注」 | 差距小于阈值时强制显示「边缘决策」并列出两个选项的数值 |
| M21 多智能体假装一致 | 冲突被平均值抹平 | 严重冲突时**降低置信度**并显式列出分歧点，而非取平均 |
| M22 静默失败 | 某个智能体崩了，系统仍输出建议 | 任一核心模块失败 → `ANALYSIS_BLOCKED` → 「当前无法给出可靠打法」 |

### 8.4 工程侧

| 风险 | 防线 |
|---|---|
| M23 巨型文件 | 单文件行数上限约 400 行，超限即拆分 |
| M24 中文最后机器翻译 | **从第一阶段**就建立 i18n 词条表，领域层只输出码值，UI 层只做映射（规范第 47 条） |

| M26 浮点误差 | 金额全部用整数筹码单位；权益用整数计数 |
| M27 随机不可复现 | 全部随机走 `infra/rng.ts`，种子入库 |
| M28 越权功能 | 不做任何自动读取牌桌/自动点击功能（合规红线，架构上不留接口） |
